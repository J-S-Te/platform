## SYS 系统管理模块

### SYS-001 用户登录

| 功能编号 | SYS-001 |
|---------|---------|
| 对应页面 | 登录页（/login） |
| 功能描述 | 用户可通过用户名密码登录，或使用钉钉扫码登录系统。系统验证身份后发放 JWT Token 并跳转至仪表盘页面。钉钉扫码登录需用户已在钉钉组织架构内且已绑定系统账号。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 登录方式切换标签 | 标签页 | 切换"密码登录"与"钉钉扫码登录"两种登录方式 |
| 用户名输入框 | 文本输入框 | 支持字母、数字、下划线、中文，长度3-20字符 |
| 密码输入框 | 密码输入框 | 支持密码可见性切换，长度8-50字符 |
| 登录按钮 | 提交按钮 | 触发表单认证请求 |
| 注册链接 | 导航链接 | 跳转至注册页（/register） |
| Token状态指示器 | 状态标签 | 显示当前Token有效状态（有效/已过期/未设置） |
| 钉钉二维码展示区 | 二维码组件 | 切换至"钉钉扫码登录"时展示，由后端调用钉钉接口生成临时登录二维码（含唯一 `tmp_code`） |
| 扫码状态提示 | 状态标签 | 展示扫码状态：待扫码 / 待确认 / 登录成功 / 已过期 / 已取消 / 未绑定（扫码成功但 unionid 未关联账号） |
| 刷新二维码按钮 | 操作按钮 | 二维码有效期（默认 5 分钟）过期后重新获取 |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户输入用户名和密码 |
| 2 | 用户点击"登录"按钮提交 |
| 3 | 前端验证输入格式：用户名3-20字符；对输入进行XSS过滤，移除 `<>:"'%;()&+` 等特殊字符 |
| 4 | 前端对密码计算 SHA-256 杂凑值，将明文密码和杂凑值一并提交至后端 |
| 5 | 后端通过 bcrypt 验证密码 + SHA-256 杂凑值双重校验 |
| 6 | 后端验证用户账号状态（permanent / temporary / timed / disabled） |
| 7 | 验证成功：返回 JWT Token、用户信息、未读通知数，跳转至仪表盘 |
| 8 | 验证失败：显示错误提示，记录失败次数至 `login_failure_records` 表 |
| 9 | 失败次数超限（>=5 次）：锁定账户 15 分钟 |
| 10 | **钉钉扫码登录**：用户切换至"钉钉扫码登录"标签，前端向后端请求获取钉钉临时登录二维码 |
| 11 | 后端调用钉钉开放平台接口生成临时登录二维码（含 `tmp_code` 及有效期），返回前端展示 |
| 12 | 用户使用钉钉 App 扫描二维码，在钉钉内确认登录授权，钉钉回调系统并携带用户 `unionid` |
| 13 | 后端根据 `unionid` 匹配已绑定的系统账号；匹配成功则签发 JWT Token 并跳转仪表盘 |
| 14 | 扫码状态异常（二维码过期 / 用户取消）：前端展示对应提示，用户可刷新二维码或改用密码登录 |
| 15 | **未绑定引导**：扫码成功但后端按 `unionid` 未匹配到系统账号时，提示"该钉钉账号尚未绑定系统账号"，并提供「前往绑定」按钮跳转至账号绑定页（/account/binding）；用户完成绑定后返回登录页重新扫码即可登录 |

#### 三、技术约束

| 约束项 | 说明 |
|--------|------|
| 密码传输 | 需加密传输（HTTPS/TLS） |
| 密码策略 | 至少包含大写字母、小写字母、数字和特殊字符中的三种，至少 8 位 |
| Token过期 | JWT Token 默认30分钟过期，过期后前端自动跳转登录页 |
| 密码存储 | 使用 bcrypt 加密存储，同时存储 SHA-256 杂凑值用于双重校验 |
| 输入安全 | 前端对输入进行XSS过滤 |
| 频率限制 | 登录接口受频率限制中间件保护（防暴力破解） |
| 钉钉集成 | 对接钉钉开放平台扫码登录能力，使用 `appKey` / `appSecret` 获取 `access_token` 与临时二维码 |
| 账号绑定 | 系统账号与钉钉 `unionid` 一对一绑定，存于用户表的 `dingtalk_unionid` 字段；未绑定用户扫码后提示"账号未与钉钉绑定" |
| 二维码有效期 | 钉钉临时登录二维码默认 5 分钟有效，过期自动失效需刷新 |
| 回调安全 | 钉钉回调需校验签名/加解密，防止伪造回调；`tmp_code` 一次性使用 |
| 隐私合规 | 仅存储钉钉 `unionid` 用于身份关联，不存储手机号等敏感信息；遵循《个人信息保护法》最小必要原则 |

#### 四、钉钉账号绑定流程

| 对应页面 | 账号绑定页（/account/binding），从登录后右上角用户菜单"账号安全"进入 |
|---------|---------|
| 功能描述 | 用户登录后可自助将系统账号与钉钉账号绑定或解绑，绑定后即可使用钉钉扫码登录（见步骤 10~14）。绑定基于已认证的登录会话，确保操作人身份明确；管理员亦可在用户管理中为账号代绑定（见 SYS-003）。 |

##### 页面元素（账号绑定页）

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 钉钉绑定状态标签 | 状态标签 | 展示当前账号钉钉绑定状态：已绑定 / 未绑定 |
| 绑定二维码展示区 | 二维码组件 | 未绑定时点击"绑定钉钉"后展示，由后端调用钉钉接口生成临时绑定二维码（含 `tmp_code`） |
| 绑定按钮 | 操作按钮 | 触发生成绑定二维码 |
| 解绑按钮 | 操作按钮 | 已绑定时清除绑定关系，含二次确认对话框 |
| 绑定操作提示 | 文本展示 | 展示绑定中 / 绑定成功 / 绑定失败（如"该钉钉账号已绑定其他用户"）等提示 |

##### 操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户登录后，从右上角用户菜单进入"账号安全 / 账号绑定"页（必须已通过身份认证） |
| 2 | 系统展示当前账号的钉钉绑定状态 |
| 3 | 未绑定用户点击"绑定钉钉"，后端调用钉钉接口生成临时绑定二维码（含 `tmp_code`） |
| 4 | 用户使用钉钉 App 扫码并在钉钉内确认授权，钉钉回调系统携带用户 `unionid` |
| 5 | 后端将当前登录账号的 `dingtalk_unionid` 字段写入该 `unionid`，状态更新为"已绑定" |
| 6 | 若 `unionid` 已绑定其他系统账号，提示"该钉钉账号已绑定其他用户，无法重复绑定"，绑定失败 |
| 7 | 已绑定用户点击"解绑"，二次确认后清除 `dingtalk_unionid`，状态变为"未绑定" |
| 8 | 绑定 / 解绑操作记录审计日志（操作人、时间、操作类型） |

##### 绑定相关技术约束

| 约束项 | 说明 |
|--------|------|
| 绑定前提 | 绑定入口必须基于已登录的已认证会话，禁止未登录或越权为他人绑定 |
| 唯一性 | 一个钉钉 `unionid` 仅可绑定一个系统账号；一个系统账号仅可绑定一个 `unionid`（双向一对一） |
| 绑定冲突 | `unionid` 已绑定其他账号时拒绝绑定，并提示明确原因 |
| 解绑影响 | 解绑后该账号不可再用钉钉扫码登录，直至重新绑定 |
| 审计记录 | 绑定 / 解绑均记录审计日志 |
| 管理员代绑定 | 管理员可在用户管理页（SYS-003）为指定账号填写或清除 `dingtalk_unionid`，适用于批量初始化场景 |

### SYS-002 用户注册

| 功能编号 | SYS-002 |
|---------|---------|
| 对应页面 | 注册页（/register） |
| 功能描述 | 新用户通过填写注册信息创建系统账号，注册成功后跳转至登录页。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 用户名输入框 | 文本输入框 | 长度3-20字符，支持字母、数字、下划线、中文 |
| 邮箱输入框 | 文本输入框 | 支持邮箱格式验证 |
| 密码输入框 | 密码输入框 | 显示密码强度要求，长度8-50字符 |
| 确认密码输入框 | 密码输入框 | 与密码一致性验证 |
| 真实姓名输入框 | 文本输入框 | 用户全名（可选） |
| 注册按钮 | 提交按钮 | 触发用户创建请求 |
| 返回登录链接 | 导航链接 | 跳转至登录页 |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户输入用户名（3~20 位，支持字母、数字、下划线、中文） |
| 2 | 用户输入邮箱（需符合标准邮箱格式） |
| 3 | 用户输入密码并确认密码（至少 8 位，包含字母和数字，且满足复杂度要求） |
| 4 | 用户输入真实姓名（可选） |
| 5 | 用户点击"注册"按钮提交 |
| 6 | 前端对输入进行XSS过滤，校验格式、用户名唯一性、两次密码一致 |
| 7 | 系统校验输入合法性，校验通过创建用户，默认角色为 `sales` |
| 8 | 注册成功，跳转至登录页；校验失败，显示具体错误提示 |

#### 三、技术约束

| 约束项 | 说明 |
|--------|------|
| 密码复杂度 | 至少 8 位，包含字母和数字，建议包含多种字符类型 |
| 用户名唯一性 | 唯一索引校验 |
| 频率限制 | 注册接口受频率限制保护 |
| 输入消毒 | 所有输入需进行消毒处理（防 SQL 注入、XSS 攻击） |

### SYS-003 用户管理

| 功能编号 | SYS-003 |
|---------|---------|
| 对应页面 | 用户管理页（/users） |
| 功能描述 | 管理员可查看、创建、编辑、删除系统用户，管理用户角色、账号状态和有效期。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 用户列表 | 数据表格 | 展示用户名、邮箱、真实姓名、角色、账号状态、创建时间 |
| 新建用户按钮 | 操作按钮 | 跳转至注册页面 |
| 搜索/筛选区域 | 搜索控件 | 按用户名、角色等条件过滤 |
| 分页控件 | 分页器 | 分页显示用户列表 |
| 编辑按钮 | 操作按钮 | 弹出编辑对话框修改用户信息 |
| 角色选择下拉框 | 下拉选择 | 角色类型 |
| 重置密码按钮 | 操作按钮 | 将用户密码重置为默认密码 |
| 解锁按钮 | 操作按钮 | 清除登录失败记录，解锁被锁定用户 |
| 钉钉绑定按钮 | 操作按钮 | 在编辑对话框中填写/清除该用户的 `dingtalk_unionid`，实现代绑定或代解绑 |
| 删除按钮 | 操作按钮 | 删除指定用户（不可删除自己） |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户（需 `user.manage` 权限）进入用户管理页面 |
| 2 | 系统分页显示所有用户列表 |
| 3 | 管理员编辑用户信息（角色、部门、电话、账号状态） |
| 4 | 管理员删除用户（物理删除） |
| 5 | 管理员为用户重置密码 |
| 6 | 管理员解锁被锁定的用户（清除登录失败记录） |
| 7 | 管理员查看用户锁定状态 |
| 8 | 管理员在编辑对话框中为用户填写 `dingtalk_unionid` 完成代绑定，或清除该字段完成代解绑（适用于批量初始化，由管理员统一维护钉钉映射） |
| 9 | 所有操作记录审计日志 |

#### 三、技术约束

| 约束项 | 说明 |
|--------|------|
| 访问权限 | 仅超级管理员和拥有 `user.manage` 权限的用户可访问 |
| 用户删除 | 为物理删除，不可删除自己 |
| 账号状态 | 支持四种类型：永久有效（permanent）、临时账号（temporary）、指定时间段（timed）、已禁用（disabled） |
| 临时账号 | 支持按有效期小时数自动过期 |
| 审计日志 | 所有操作记录审计日志 |
| 代绑定约束 | 管理员代填 `dingtalk_unionid` 时须校验唯一性：该 `unionid` 不得已绑定其他账号，否则拒绝保存 |

### SYS-004 角色与权限管理

| 功能编号 | SYS-004 |
|---------|---------|
| 对应页面 | 无独立页面（内嵌于用户管理） |
| 功能描述 | 系统预置 6 种角色，采用"角色权限 + 用户自定义权限"双重控制模式。最终权限 = 角色默认权限 ∪ 用户自定义权限。 |

#### 一、系统预置角色

| 角色 | 标识 | 默认权限 | 说明 |
|------|------|---------|------|
| 超级管理员 | `admin` | 全部权限 | 系统最高权限，可管理所有资源 |
| 销售总监 | `sales_director` | 仪表盘、合同查看、客户查看、审批 | 审批销售提交的合同 |
| 技术总监 | `tech_director` | 仪表盘、合同查看、客户查看、审批 | 审批技术相关合同 |
| 财务总监 | `finance_director` | 仪表盘、合同查看、客户查看、审批 | 审批财务相关合同 |
| 销售人员 | `sales` | 仪表盘、查看/创建合同、查看/创建客户 | 只能查看和操作自己的合同 |
| 审计管理员 | `audit_admin` | 仪表盘、审计查看、合同/客户/审批只读 | 负责操作日志审计 |

#### 二、权限清单

| 权限标识 | 说明 | 适用角色 |
|---------|------|---------|
| `all` | 全部权限 | 超级管理员 |

### CON-002 合同生命周期状态管理

| 功能编号 | CON-002 |
|---------|---------|
| 对应页面 | 合同详情页 |
| 功能描述 | 合同贯穿完整生命周期，从草稿到归档共 9 种状态，支持状态流转控制。 |

#### 一、合同状态流转

```
draft(草稿) -> pending(待审批) -> approved(已批准) -> active(已生效)
-> in_progress(执行中) -> pending_pay(待付款) -> completed(已完成) -> archived(已归档)
                                                                          ^
                                                terminated(已终止) ---------+
```

#### 二、页面元素（合同详情页）

| 组件/控件 | 说明 |
|----------|------|
| 合同基本信息展示区 | 合同编号、标题、客户、类型、金额、币种、状态、日期、付款条款、内容 |
| 合同状态标签 | 当前状态高亮显示 |
| 状态变更操作按钮 | 根据当前状态和权限显示可用操作 |
| 生命周期事件时间线 | 按时间倒序展示所有状态变更记录 |
| 状态变更申请表 | 关键状态变更需审批（含变更原因输入） |
| 状态变更记录 | 展示历史状态变更申请及审批状态 |

#### 三、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户查看合同，系统展示当前状态及生命周期时间线 |
| 2 | 用户提交合同进入审批流程（草稿 -> 待审批） |
| 3 | 审批通过后状态自动流转（待审批 -> 已批准 -> 已生效） |
| 4 | 用户更新合同状态（如执行中、待付款、已完成） |
| 5 | 用户申请关键状态变更（如归档、终止），需管理员审批 |
| 6 | 系统每日定时任务自动归档已过期合同（结束日期 < 当前日期） |

#### 四、技术约束

| 约束项 | 说明 |
|--------|------|
| 状态记录 | 状态变更自动记录到 `contract_lifecycle_events` 表 |
| 审批要求 | 关键状态变更（归档、终止、执行中、待付款）需经过审批 |
| 定时任务 | 系统定时任务每天凌晨检查过期合同并自动归档 |
| 自动通知 | 自动归档同时创建通知给销售人员、销售总监和管理员 |
| 状态变更方式 | 支持直接变更和审批变更两种方式；archived/terminated 需要审批，其他可直接变更 |

### CON-008 合同自动生成

| 功能编号 | CON-008 |
|---------|---------|
| 对应页面 | 合同创建/编辑页（/contracts/new、/contracts/:id/edit） |
| 功能描述 | 用户在创建或编辑合同时，仅需录入合同必要关键信息（如编号、标题、客户、金额、服务类型、系统名称、系统等级、付款条款），选择已启用的合同模板后，系统调用该模板自动将占位符替换为关键信息，生成完整合同正文；用户可在此基础上手动微调后保存。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 模板选择下拉框 | 下拉选择 | 仅展示"启用"状态且适用当前合同类型的模板 |
| 关键信息录入区 | 表单组件 | 合同编号、标题、客户选择、合同类型、金额、货币类型、服务类型、系统名称（选填）、系统等级（选填）、付款条款等必要字段（与 CON-007 模板占位符对应的字段；其中系统名称、系统等级为选填） |
| 一键生成按钮 | 操作按钮 | 点击后调用所选模板，将关键信息填充至占位符，生成合同全文 |
| 合同正文预览区 | 富文本/文本区 | 展示根据模板生成的完整合同正文，支持手动编辑调整 |
| 生成状态提示 | 状态标签 | 展示生成状态：待生成 / 生成中 / 已生成 / 生成失败（占位符缺失） |
| 重新生成按钮 | 操作按钮 | 修改关键信息或切换模板后可重新生成 |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户（需 `contract.create` 权限）进入合同创建/编辑页 |
| 2 | 用户从模板选择下拉框中选择一个已启用模板（不选则走原手动录入正文流程） |
| 3 | 用户填写必要关键信息（编号、标题、客户、金额、服务类型、系统名称、系统等级、付款条款等，其中系统名称与系统等级为选填） |
| 4 | 用户点击「一键生成」，系统加载所选模板正文，将预置占位符替换为对应关键信息 |
| 5 | 系统校验占位符是否全部匹配：匹配成功则生成完整合同正文并展示在预览区；存在未匹配占位符则提示"以下字段未填写：XXX"，生成失败 |
| 6 | 用户在预览区对生成的合同正文进行必要微调（如补充模板未覆盖的个性化条款） |
| 7 | 用户点击「保存」，合同以"草稿"状态创建/更新，正文内容随合同一并保存 |

#### 三、技术约束

| 约束项 | 说明 |
|--------|------|
| 模板来源 | 仅调用 CON-007 中状态为"启用"的模板 |
| 字段映射 | 系统按 CON-007 占位符字段名自动匹配合同录入字段，各占位符来源如下：合同标题←标题；甲方名称←系统配置（我方机构名称）；乙方名称←CUS-001 查询结果（客户/供应商名称）；合同金额←金额（含货币类型）；服务类型←用户输入；系统名称←用户输入（选填）；系统等级←用户输入（选填）；付款条款←用户输入 |
| 占位符与合同实体关系 | 模板占位符（含服务类型/系统名称/系统等级）对应合同录入字段；合同实体本身的签订/开始/结束日期不属于模板占位符，仍按 CON-001 录入并存储，但不参与正文自动填充 |
| 生成引擎 | 后端基于模板正文做占位符替换（字符串模板引擎），不依赖外部大模型，确保生成结果可追溯、可控 |
| 占位符校验 | 生成前校验所有占位符均有对应值；缺失值阻断生成并提示用户补全 |
| 正文存储 | 生成的合同正文作为合同 `content` 字段存储，与模板解耦（后续编辑模板不影响已生成合同） |
| 权限要求 | `contract.create`（生成并保存合同）；`contract_template.read`（读取模板内容） |
| 兼容性 | 未选择模板时，合同正文由用户手动录入，与原 CON-001 流程完全兼容 |
| 审计记录 | 合同自动生成操作记录审计日志（所用模板、生成时间、操作人） |

| 工作流状态展示 | 当前级别、总级别、各节点状态 |
| 催办按钮 | 发送提醒给当前审批人 |
| 待审批数量提示 | 侧边栏菜单上红点显示待办数量 |

#### 三、操作步骤

| 步骤 | 操作说明 |

| 3 | 销售总监查看待审批列表并审批（通过/拒绝，需 `approval.process` 权限） |
| 4 | 一级通过后自动流转至技术总监审批 |
| 5 | 二级通过后自动流转至财务总监审批 |

| 审批回滚 | 审批支持回滚操作 |
| 工作流引擎 | 实现多级审批工作流引擎，支持审批流程创建、审批级别管理、审批人角色匹配 |

#### 二、规则配置说明

系统预置以下简化审批规则，支持用户自定义扩展：

| 规则编号 | 触发条件 | 审批流程 |
|---------|---------|---------|
| R001 | 新签金额 ≤ XX 万 **且** 服务类型=标准服务 **且** 客户信用等级=A 级 | 仅销售总监 + 财务经理（跳过技术审核） |

| 条件字段 | 可选值 | 说明 |

### APP-005 审批功能增强

| 功能编号 | APP-005 |
|---------|---------|
| 对应页面 | 审批详情页（/approval/:id） |
| 功能描述 | 系统在基础审批功能之上，增强加签、转交、退回、撤回等操作能力；审批表单清晰展示关键字段变化对比；支持备注说明、评论；支持流程待办提醒与催办。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 审批表单 | 表单组件 | 展示合同信息及关键字段变更对比（高亮变化字段） |
| 审批操作栏 | 操作按钮组 | 同意、拒绝、加签、转交、退回、撤回 |
| 备注输入框 | 文本域 | 审批时填写备注说明 |
| 评论区 | 评论组件 | 审批流程中的评论记录与新增评论 |
| 流程可视化 | 流程图组件 | 展示当前审批节点、已完成节点、待处理节点 |
| 待办提醒设置 | 配置控件 | 设置提醒方式（站内信/邮件）和提醒频率 |
| 催办按钮 | 操作按钮 | 向当前审批人发送催办通知 |

#### 二、功能详细说明

**1. 加签**
- 当前审批人可将其他人员加入当前审批节点（会签/或签）
- 加签人员完成审批后，流程继续向下流转
- 支持加签说明，记录加签原因

**2. 转交**
- 当前审批人可将审批任务转交给其他人员处理
- 转交后，原审批人不再参与该节点审批
- 需填写转交原因，系统记录转交操作日志

**3. 退回至任意节点**
- 当前审批人可将流程退回至已通过的任意历史节点
- 退回时选择目标节点，填写退回原因
- 目标节点审批人重新审批后，流程按原路径继续

**4. 撤回**
- 审批提交人可在审批完成前撤回申请
- 撤回后合同状态回退至「草稿」状态
- 需填写撤回原因，系统通知所有已审批人员

**5. 关键字段变化对比**
- 审批表单自动比对当前版本与上一版本的字段差异
- 变化字段高亮显示（如金额、服务内容、条款等）
- 支持展开「变更对比」面板查看详细差异

**6. 备注说明与评论**
- 每次审批操作均支持填写备注说明（必填/选填可配置）
- 评论区支持审批流程中所有参与人员发表评论
- 评论支持 @ 提及功能，被提及人员收到通知

**7. 待办提醒与催办**
- 系统自动向待审批人员发送待办提醒（站内信，可选邮件）
- 提醒频率可配置（每日一次 / 每 4 小时一次）
- 申请人或管理员可手动催办，向当前审批人发送催办通知
- 催办记录记入审计日志

#### 三、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 审批人打开审批详情页，查看合同信息及字段变更对比 |
| 2 | 审批人选择操作：同意 / 拒绝 / 加签 / 转交 / 退回 / 撤回 |
| 3 | 填写备注说明或退回/撤回原因 |
| 4 | 如需加签或转交，选择目标人员并确认 |
| 5 | 提交操作，系统记录日志并通知下一节点审批人 |
| 6 | 申请人或管理员可随时点击「催办」向当前审批人发送提醒 |

#### 四、技术约束

| 约束项 | 说明 |
|--------|------|
| API 接口 | `/api/approvals/:id/sign`（加签）；`/api/approvals/:id/transfer`（转交）；`/api/approvals/:id/return`（退回）；`/api/approvals/:id/withdraw`（撤回）；`/api/approvals/:id/urge`（催办） |
| 字段对比 | 基于合同版本历史，通过 `version_id` 关联比对 |
| 通知方式 | 站内信（实时）；邮件（可选，需配置 SMTP） |
| 权限要求 | 加签/转交/退回/撤回：当前审批节点处理人；催办：申请人或 `approval.manage` 权限 |
| 退回限制 | 仅可退回至已通过的节点，不可退回至未来节点 |

### SIG-002 回传跟踪与 OCR 识别

| 功能编号 | SIG-002 |
|---------|---------|
| 对应页面 | 合同回传跟踪页（/contract/:id/tracking） |
| 功能描述 | 系统跟踪合同回传进度，超期未回传自动提醒催收；合同专员扫描上传回传件后，系统通过 OCR 自动识别印章、签名、日期，验证通过后状态变更为「已签署」。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 回传状态展示 | 状态标签 | 展示当前回传状态（待回传 / 已回传 / 已签署 / 逾期） |
| 逾期提醒记录 | 时间线组件 | 展示系统自动发送的催收提醒记录 |
| 上传回传件按钮 | 操作按钮 | 上传回传合同扫描件（PDF/图片） |
| OCR 识别结果展示 | 结果面板 | 展示 OCR 识别的印章、签名、日期信息及置信度 |
| 人工确认按钮 | 操作按钮 | OCR 识别通过后，专员人工确认，状态变更为「已签署」 |
| 催收提醒按钮 | 操作按钮 | 手动发送催收提醒通知 |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 合同状态为「已寄出」后，系统启动回传跟踪计时（默认 15 天） |
| 2 | 距寄出超过 15 天未回传：系统自动发送催收提醒通知销售人员 and 合同专员 |
| 3 | 合同专员收到回传件后，扫描上传至系统（支持 PDF 或图片格式） |
| 4 | 系统调用 OCR 服务自动识别：印章（是否存在、是否清晰）、签名（是否存在）、签署日期（是否填写） |
| 5 | OCR 识别通过（置信度 ≥ 85%）：系统提示「OCR 识别通过，请人工确认」 |
| 6 | 专员人工确认无误后，点击「确认签署」，合同状态变更为「已签署」 |
| 7 | 系统自动通知销售人员："合同已签署完成，状态已更新。" |

#### 三、OCR 识别规则

| 识别项 | 识别要求 | 处理方式 |
|--------|---------|---------|
| 印章识别 | 检测红色圆形印章图案，识别印章内文字 | 置信度 ≥ 85% 为通过；否则提示人工复核 |
| 签名识别 | 检测手写签名区域，确认存在签名笔迹 | 检测到签名区域即通过；否则提示人工复核 |
| 签署日期识别 | 识别日期格式文本（如"2026 年 07 月 05 日"） | 识别到有效日期即通过；日期缺失提示人工补填 |

#### 四、技术约束

| 约束项 | 说明 |
|--------|------|
| API 接口 | `/api/contracts/:id/upload-return`（上传回传件）；`/api/contracts/:id/ocr-verify`（OCR 识别）；`/api/contracts/:id/confirm-sign`（确认签署） |
| OCR 服务 | 对接第三方 OCR API（如腾讯云 OCR / 阿里云 OCR）或使用本地 OCR 引擎 |
| 逾期提醒 | 基于定时任务（Cron）每日检查，超期自动发送提醒 |
| 提醒通知模板 | "【逾期提醒】合同《{contract_title}》已寄出 {days} 天，尚未收到回传件，请及时跟进。" |
| 权限要求 | `contract.sign`（上传回传件、OCR 识别、确认签署）；`contract.view`（查看回传状态） |
| 回传文件存储 | 回传件存于 `contract_documents` 表，`doc_type` 标记为 `returned` |

### AUD-002 登录安全

| 功能编号 | AUD-002 |
|---------|---------|
| 对应页面 | 无独立页面 |
| 功能描述 | 系统对登录失败次数进行监控，超过阈值自动锁定账户，防止暴力破解攻击。 |

#### 一、操作流程

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户登录失败：系统记录失败次数和失败时间 |
| 2 | 失败次数达到 5 次：账户锁定 15 分钟 |
| 3 | 锁定期间：用户无法登录，提示"账户已锁定，请稍后再试" |
| 4 | 锁定时间过后：失败记录自动清除（30 分钟无操作重置） |
| 5 | 管理员可手动解锁用户（清除登录失败记录） |

#### 二、技术约束

| 约束项 | 说明 |
|--------|------|
| 最大登录尝试次数 | 5 次 |
| 锁定时长 | 15 分钟 |
| 失败记录重置时间 | 30 分钟（距首次失败） |
| 锁定状态存储 | 存于 `login_failure_records` 表 |
| 频率限制 | 登录接口受频率限制中间件保护（防暴力破解） |
