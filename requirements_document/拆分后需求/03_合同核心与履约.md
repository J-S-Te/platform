# 03 合同核心与履约需求

## 1. 领域边界

本文件覆盖合同聚合、生命周期、履约、归档和到期提醒。建议核心实体包括 `Contract`、`ContractParty`、`ContractVersion`、`PaymentPlan`、`ContractChange`；业务表以 `contract_*` 为前缀，由合同模块独占访问。

## 2. 架构对齐后的补充要求

### 2.1 合同状态与并发

- 合同状态机属于合同应用服务，不能散落在 Controller；状态变更应通过命令和领域事件完成。
- 所有修改使用 `version` 乐观锁；保存、提交、审批结果回写、归档和终止需要处理并发冲突。
- 业务状态、审批实例状态和签署状态分离建模，避免用一个状态字段表达全部流程。

### 2.2 数据范围与审计

- 合同查询、导出、履约查看和归档操作均必须传入 `DataScope`，由仓储层强制生成查询条件。
- 合同创建、编辑、提交、状态变更、付款计划变更、归档、到期提醒处理均需记录审计事件和变更集。
- 合同引用人员时存 `user_id` 与姓名快照；不复制平台用户主数据。

### 2.3 到期与后台任务

- 到期扫描为模块化单体内的 Scheduler/Worker 任务；任务定义和执行记录持久化到 MySQL，不使用 Redis。
- 提醒阈值属于运行期配置，放入配置命名空间并支持版本、发布、回滚；任务执行结果写审计/运行日志，不把运行日志写进业务表。

| 备注字段 | 备注字段由纯文本扩展为"文本 + 图片 URL 数组"结构，向后兼容原有纯文本数据 |

### CON-002 合同生命周期状态管理

| 功能编号 | CON-002 |
|---------|---------|
| 对应页面 | 合同详情页 |
| 功能描述 | 合同贯穿完整生命周期，从草稿到归档共 9 种状态，支持状态流转控制。 |

#### 一、合同状态流转

```
draft(草稿) -> pending(待审批) -> approved(已批准) -> active(已生效)
-> in_progress(执行中) -> pending_pay(待付款) -> completed(已完成) -> archived(已归档)
                                                                          ^
                                                terminated(已终止) ---------+
```

#### 二、页面元素（合同详情页）

| 组件/控件 | 说明 |
|----------|------|
| 合同基本信息展示区 | 合同编号、标题、客户、类型、金额、币种、状态、日期、付款条款、内容 |
| 合同状态标签 | 当前状态高亮显示 |
| 状态变更操作按钮 | 根据当前状态和权限显示可用操作 |
| 生命周期事件时间线 | 按时间倒序展示所有状态变更记录 |
| 状态变更申请表 | 关键状态变更需审批（含变更原因输入） |
| 状态变更记录 | 展示历史状态变更申请及审批状态 |

#### 三、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户查看合同，系统展示当前状态及生命周期时间线 |
| 2 | 用户提交合同进入审批流程（草稿 -> 待审批） |
| 3 | 审批通过后状态自动流转（待审批 -> 已批准 -> 已生效） |
| 4 | 用户更新合同状态（如执行中、待付款、已完成） |
| 5 | 用户申请关键状态变更（如归档、终止），需管理员审批 |
| 6 | 系统每日定时任务自动归档已过期合同（结束日期 < 当前日期） |

#### 四、技术约束

| 约束项 | 说明 |
|--------|------|
| 状态记录 | 状态变更自动记录到 `contract_lifecycle_events` 表 |
| 审批要求 | 关键状态变更（归档、终止、执行中、待付款）需经过审批 |
| 定时任务 | 系统定时任务每天凌晨检查过期合同并自动归档 |
| 自动通知 | 自动归档同时创建通知给销售人员、销售总监和管理员 |
| 状态变更方式 | 支持直接变更和审批变更两种方式；archived/terminated 需要审批，其他可直接变更 |

### CON-005 合同归档

| 功能编号 | CON-005 |
|---------|---------|
| 对应页面 | 合同详情页 |
| 功能描述 | 用户可手动归档已完成的合同，系统亦支持自动归档过期的合同。归档后合同进入只读状态。 |

#### 一、页面元素

| 组件/控件 | 说明 |
|----------|------|
| 归档按钮 | 对 completed 状态的合同触发归档操作 |
| 归档确认对话框 | 确认归档操作 |
| 归档状态标签 | 已归档（archived） |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 合同执行完成后状态变为 completed |
| 2 | 用户申请归档合同（需 `contract.edit` 权限） |
| 3 | 管理员审批归档申请 |
| 4 | 审批通过：合同状态变更为 archived，不可再修改 |
| 5 | 系统每日自动检查并归档过期合同（触发条件：结束日期已过 且 状态为 active 或 in_progress） |
| 6 | 归档操作记录生命周期事件 |
| 7 | 自动归档同时通知合同创建人、销售总监和管理员 |

#### 三、技术约束

| 约束项 | 说明 |
|--------|------|
| 手动归档 | 需状态变更审批流程 |
| 自动归档 | 触发条件：合同结束日期已过 且 状态为 active 或 in_progress |
| 归档后状态 | 归档后合同为只读状态，不可修改 |
| 通知机制 | 自动归档同时通知相关人员 |

### CON-006 合同到期提醒

| 功能编号 | CON-006 |
|---------|---------|
| 对应页面 | 到期提醒页（/reminders） |
| 功能描述 | 系统对即将到期的合同进行提醒通知，用户可设置提醒规则和手动发送提醒。 |

#### 一、页面元素

| 组件/控件 | 说明 |
|----------|------|
| 即将到期合同列表 | 展示合同编号、标题、客户、结束日期、剩余天数 |
| 已设置提醒列表 | 展示提醒类型、提醒日期、提前天数、是否已发送、发送时间 |
| 创建提醒按钮 | 填写提醒类型、提醒日期、提前天数 |
| 提醒设置表单 | 提醒类型、提醒日期、提前天数 |
| 发送提醒按钮 | 手动触发发送提醒 |
| 到期天数参数 | 默认 30 天可在请求中配置 |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户查看即将到期的合同列表（可配置提前天数范围，默认 30 天） |
| 2 | 用户为合同创建到期提醒（需 `approval.process` 权限） |
| 3 | 用户手动发送提醒通知（需 `approval.process` 权限） |
| 4 | 系统展示提醒状态（已发送/未发送） |

#### 三、技术约束

| 约束项 | 说明 |
|--------|------|
| 提醒类型 | 包括：付款到期（expire_payment）、合同到期（expire_end） |
| 提前提醒 | 支持设置提前提醒天数 |
| 通知推送 | 提醒通知推送到用户通知中心 |
| 即将到期列表 | 到期天数参数默认 30 天，可在请求中配置 |
