# 07 审计、安全与可观测性需求

## 1. 领域边界

审计日志记录“谁在何时因何请求改变或访问了什么业务数据”；运行日志记录程序运行诊断信息。两者必须分离：审计事件进入基础能力平台审计中心，运行日志/Trace/Metric 采用结构化日志和 OpenTelemetry/OTLP。

## 2. 架构对齐后的补充要求

### 2.1 审计上报

- 合同系统在本地 MySQL `audit_outbox` 写入事件，与业务事务协调；由后台任务经 SDK/API 上报。
- 事件至少包含 `event_id`、发生时间、租户、应用、环境、主体、资源、动作、结果、风险等级、请求/Trace ID、对象标识、变更摘要。
- 平台按 `event_id` 幂等接收；失败重试、死信/人工处理要可观测。
- 操作审计与数据变更审计分别存 `audit_event` 和 `audit_change` 的职责范围；敏感字段遵循脱敏/最小化原则。

### 2.2 登录与安全

- 登录安全属于 IAM/Security 模块：会话、失败尝试、锁定、MFA、风险事件和外部身份绑定由平台统一管理。
- 业务应用需处理认证失效、权限拒绝、平台故障和审计重试，但不维护自己的密码表和登录失败表。
- 高风险操作可启用 Step-up Authentication；授权服务不可用时高风险操作失败关闭。

### 2.3 可观测性

- 每个合同服务请求携带 Request ID/Trace ID 和应用、环境、租户等资源标签。
- 审计查询、运行日志查询、指标和告警入口分离；禁止用审计表替代应用日志。

## 3. 原始需求摘录（完整保留）

### AUD-001 审计日志

| 功能编号 | AUD-001 |
|---------|---------|
| 对应页面 | 审计日志页（/audit） |
| 功能描述 | 系统自动记录所有用户操作行为，审计管理员可查询、删除和导出审计日志，确保操作可追溯和合规。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 审计日志列表 | 数据表格 | 展示操作人、操作动作、模块、方法、路径、IP 地址、状态码、时间 |
| 搜索/筛选区域 | 筛选控件 | 按用户、操作、模块、时间范围筛选 |
| 分页控件 | 分页器 | 分页显示日志 |
| 导出日志按钮 | 操作按钮 | 导出筛选后的日志数据 |
| 删除按钮 | 操作按钮 | 删除单条日志 |
| 批量删除按钮 | 操作按钮 | 勾选多条日志后批量删除 |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 审计管理员进入审计日志页面（需 `audit.view` 权限） |
| 2 | 系统分页显示审计日志，支持多条件筛选 |
| 3 | 管理员删除指定日志（单条或批量，需 `user.manage` 权限） |
| 4 | 管理员导出审计日志为文件（需 `audit.view` 权限） |

#### 三、技术约束

| 约束项 | 说明 |
|--------|------|
| 自动记录 | 审计日志通过中间件自动记录（每次 API 请求自动记录） |
| 记录字段 | 用户 ID、用户名、操作动作、模块、HTTP 方法、请求路径、客户端 IP、User-Agent、请求内容、响应内容、HTTP 状态码 |
| 存储隔离 | 审计日志表独立存储，与业务数据隔离 |
| 访问权限 | 仅 `audit_admin` 角色和超级管理员可访问 |
| 频率限制 | 审计日志查询接口受频率限制保护 |

### AUD-002 登录安全

| 功能编号 | AUD-002 |
|---------|---------|
| 对应页面 | 无独立页面 |
| 功能描述 | 系统对登录失败次数进行监控，超过阈值自动锁定账户，防止暴力破解攻击。 |

#### 一、操作流程

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户使用已识别账号登录失败：系统记录失败次数、失败时间和安全摘要，不记录密码或令牌等认证秘密。 |
| 2 | 当前有效失败次数达到租户登录策略阈值（默认 5 次）：账户锁定默认 15 分钟，并创建一条待处置的 `ACCOUNT_LOCKED` 风险事件。 |
| 3 | 锁定期间：用户无法登录，接口返回账户锁定状态和锁定截止时间。 |
| 4 | 对于未锁定账号，超过失败重置窗口（默认连续 30 分钟未发生新的失败）后，旧失败记录不再计入后续锁定阈值。 |
| 5 | 具有锁定账号解锁权限的管理员可手动解锁；系统清除当前失败计数、关闭关联锁定风险事件，并保留解锁处置记录。 |

#### 二、技术约束

| 约束项 | 说明 |
|--------|------|
| 默认最大登录尝试次数 | 5 次；可由具备登录策略更新权限的管理员按租户配置为 1–20 次。 |
| 默认锁定时长 | 15 分钟；可按租户配置为 60–86400 秒。 |
| 默认失败记录重置时间 | 30 分钟滚动窗口；可按租户配置为 60–86400 秒。 |
| 策略与失败记录存储 | 策略存于 `sec_login_policy`；失败明细存于 `sec_login_attempt`；账户实际锁定截止时间存于 `iam_account.locked_until`。 |
| 风险事件记录与处置 | 达到阈值创建 `sec_risk_event` 中状态为 `OPEN` 的 `ACCOUNT_LOCKED` 事件；安全管理员可查询、填写处置说明后解决，管理员解锁会自动关闭关联锁定事件并新增解锁处置记录。 |
| 访问控制 | 登录策略、锁定账号和风险事件接口均由 Gin 权限中间件保护；权限代码以 SQL 迁移注册。 |
| 频率限制 | 登录入口采用进程内固定窗口限流（每个来源地址默认每分钟 30 次），超过限制返回 HTTP 429。单实例单体不依赖 Redis；部署为多实例前必须评估共享限流方案。 |
