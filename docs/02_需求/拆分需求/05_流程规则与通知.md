# 05 流程、规则与通知需求

## 1. 领域边界

流程模块负责流程定义、实例、任务和动作；合同模块通过 `WorkflowService` 启动/完成/取消流程，不由流程模块直接修改合同表。通知模块负责模板、投递和状态；合同模块通过领域事件触发通知。

## 2. 架构对齐后的补充要求

### 2.1 流程协作

- 合同模块提交审批时调用 `WorkflowService.Start`；审批完成后由 `workflow.instance.approved`、`workflow.instance.rejected` 等领域事件驱动合同状态更新。
- `WorkflowTask` 的审批人可以是用户、角色、组织或岗位解析结果；任务完成时固化实际处理人和授权快照。
- 工作流不直接 UPDATE 合同、客户或通知表，避免跨模块数据耦合。

### 2.2 规则与配置

- 审批规则使用可版本化的定义 JSON 和配置发布流程；保存、启停、发布、回滚均审计。
- 规则条件由合同金额、相对方信用、合同类型等可解释字段构成；规则命中结果保存输入快照和规则版本。
- 规则执行异常默认走保守流程（不跳过审批节点），并记录风险事件/运行日志。

### 2.3 通知

- 站内信、邮件、短信、Webhook 为通知渠道；投递记录与业务事件分离。
- 合同模块不直接依赖通知数据库；通过应用服务或领域事件创建通知。
- 通知中的合同/流程跳转必须在目标页面重新鉴权，不能将通知视作授权凭证。

## 3. 原始需求摘录（完整保留）

### APP-001 多级审批工作流

| 功能编号 | APP-001 |
|---------|---------|
| 对应页面 | 审批管理页（/approvals） |
| 功能描述 | 合同提交后进入三级审批流程，依次由销售总监、技术总监、财务总监审批，全部通过后合同生效。 |

#### 一、审批流程

```
销售人员提交合同 -> 销售总监（一级）--拒绝--> 退回申请人
                   -> 技术总监（二级）--拒绝--> 退回申请人
                   -> 财务总监（三级）--拒绝--> 退回申请人
                   -> 审批完成（合同状态变更为"已批准"）
```

#### 二、页面元素

| 组件/控件 | 说明 |
|----------|------|
| 待审批列表 | 我的待审批合同（编号、标题、提交人、提交时间、当前审批级别） |
| 审批记录列表 | 合同编号、审批级别、审批人、状态、审批时间、意见 |
| 审批操作区 | 通过、拒绝按钮 + 审批意见输入 |
| 工作流状态展示 | 当前级别、总级别、各节点状态 |
| 催办按钮 | 发送提醒给当前审批人 |
| 待审批数量提示 | 侧边栏菜单上红点显示待办数量 |

#### 三、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 销售人员提交合同进入审批（需 `contract.create` 权限） |
| 2 | 系统创建工作流，按三级审批流程自动分配审批人 |
| 3 | 销售总监查看待审批列表并审批（通过/拒绝，需 `approval.process` 权限） |
| 4 | 一级通过后自动流转至技术总监审批 |
| 5 | 二级通过后自动流转至财务总监审批 |
| 6 | 三级全部通过：合同状态变更为"已批准"，自动流转至"已生效" |
| 7 | 任一级拒绝：合同状态回退至"草稿"，通知申请人 |
| 8 | 用户可催办审批（发送提醒给当前审批人） |
| 9 | 合同创建者可撤回待审批状态的申请 |

#### 四、技术约束

| 约束项 | 说明 |
|--------|------|
| 完整性验证 | 审批工作流支持 SHA-256 完整性哈希验证 |
| 超时机制 | 审批支持超时机制（默认 72 小时），超时后标记为过期 |
| 通知机制 | 审批操作自动发送通知给相关用户 |
| 审批记录 | 包含审批级别、审批人角色、审批时间、审批意见 |
| 审批回滚 | 审批支持回滚操作 |
| 工作流引擎 | 实现多级审批工作流引擎，支持审批流程创建、审批级别管理、审批人角色匹配 |

### APP-002 状态变更审批

| 功能编号 | APP-002 |
|---------|---------|
| 对应页面 | 审批管理页 |
| 功能描述 | 合同的关键状态变更（归档、终止、执行中、待付款）需提交申请并经管理员审批。 |

#### 一、页面元素

| 组件/控件 | 说明 |
|----------|------|
| 待审批状态变更列表 | 合同编号、当前状态、目标状态、申请人、申请原因、申请时间 |
| 状态变更申请表单 | 原状态、目标状态、变更原因 |
| 审批操作按钮 | 通过/拒绝 + 意见输入框 |
| 申请详情展示 | 变更原因、申请人、申请时间 |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户提交状态变更申请（需 `contract.edit` 权限），填写变更原因 |
| 2 | 管理员查看待审批状态变更列表（需 `approval.process` 权限） |
| 3 | 管理员审批通过：合同状态变更至目标状态 |
| 4 | 管理员审批拒绝：状态不变，申请人收到拒绝通知 |

#### 三、技术约束

| 约束项 | 说明 |
|--------|------|
| 申请记录 | 状态变更申请记录原状态、目标状态、申请人、审批人、审批意见 |
| 自动更新 | 审批通过/拒绝后自动更新合同状态 |
| 日志记录 | 审批操作记录审计日志和生命周期事件 |
| 变更范围 | 归档、终止、执行中、待付款均需审批 |

### APP-003 通知与消息管理

| 功能编号 | APP-003 |
|---------|---------|
| 对应页面 | 集成于系统顶部导航栏 |
| 功能描述 | 系统向用户推送审批提醒、审批结果、状态变更、合同到期等通知消息。 |

#### 一、页面元素

| 组件/控件 | 说明 |
|----------|------|
| 顶部导航栏通知图标 | 红色角标显示未读数量 |
| 通知下拉列表 | 显示通知标题、内容、时间、已读/未读状态 |
| 标记已读按钮 | 标记单条通知为已读 |
| 全部标记已读 | 批量标记所有通知为已读 |
| 删除按钮 | 删除单条通知 |
| 清空全部按钮 | 删除全部通知 |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 系统自动生成通知（审批结果、状态变更、合同到期等） |
| 2 | 用户登录后系统推送未读通知，返回未读通知数和通知列表 |
| 3 | 用户点击通知图标查看通知列表 |
| 4 | 用户标记单条通知为已读；或点击"全部已读"标记所有为已读 |
| 5 | 用户删除单条通知或清空全部通知 |
| 6 | 点击通知自动标记为已读，可跳转至关联合同或审批页面 |

#### 三、技术约束

| 约束项 | 说明 |
|--------|------|
| 通知类型 | 审批提醒（approval_reminder）、审批通过（approved）、审批拒绝（rejected）、待审批（pending_approval）、状态变更（status_change） |
| 自动推送 | 登录时自动返回未读通知数和通知列表 |
| 关联跳转 | 通知关联合同 ID 和工作流 ID，便于跳转至相关页面 |

### APP-004 审批规则引擎

| 功能编号 | APP-004 |
|---------|---------|
| 对应页面 | 审批规则配置页（/approval-rules） |
| 功能描述 | 系统支持可配置的审批规则引擎，根据合同金额、服务类型、客户信用等级等条件自动简化审批流程，减少不必要的审批节点，提升审批效率。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 规则列表 | 数据表格 | 展示已配置的审批规则（条件、适用流程、生效状态） |
| 新增规则按钮 | 操作按钮 | 打开规则配置弹窗 |
| 规则编辑按钮 | 操作按钮 | 修改已有规则 |
| 启用/禁用开关 | 开关控件 | 控制规则是否生效 |
| 规则配置弹窗 | 弹窗 | 配置触发条件与对应审批流程 |

#### 二、规则配置说明

系统预置以下简化审批规则，支持用户自定义扩展：

| 规则编号 | 触发条件 | 审批流程 |
|---------|---------|---------|
| R001 | 新签金额 ≤ XX 万 **且** 服务类型=标准服务 **且** 客户信用等级=A 级 | 仅销售总监 + 财务经理（跳过技术审核） |
| R002 | 合同类型=框架合同 **且** 子订单金额未超出框架范围 | 仅销售总监 |
| R003 | 合同类型=续签 **且** 条款与原合同完全一致 | 仅财务经理 |

**规则条件字段说明：**

| 条件字段 | 可选值 | 说明 |
|---------|---------|------|
| 合同金额 | 数值区间（如 ≤100 万） | 支持大于、小于、等于、区间比较 |
| 服务类型 | 标准服务 / 定制服务 / 咨询服务 | 取自合同类型配置 |
| 客户信用等级 | A 级 / B 级 / C 级 | 取自客户管理模块 |
| 合同类型 | 新签 / 续签 / 框架合同 / 子订单 | 系统自动判断 |
| 条款一致性 | 是 / 否 | 系统比对当前合同与关联历史合同 |

#### 三、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 管理员进入审批规则配置页面（需 `approval_rule.manage` 权限） |
| 2 | 点击「新增规则」，配置触发条件（支持多条件 AND/OR 组合） |
| 3 | 配置满足条件时跳过的审批节点和保留的审批节点 |
| 4 | 保存规则并设为启用状态 |
| 5 | 合同提交审批时，系统自动匹配适用规则，按简化流程路由 |

#### 四、技术约束

| 约束项 | 说明 |
|--------|------|
| API 接口 | `/api/approval-rules` (GET/POST/PUT/DELETE) |
| 规则存储 | `approval_rules` 表（条件表达式 JSON 存储） |
| 权限要求 | `approval_rule.manage`（规则配置）；`approval.view`（规则查看） |
| 规则引擎 | 基于条件表达式解析，实时匹配合同提交请求 |
| 规则优先级 | 支持设置规则优先级，多规则匹配时按优先级排序取最高优先级规则 |

### APP-005 审批功能增强

| 功能编号 | APP-005 |
|---------|---------|
| 对应页面 | 审批详情页（/approval/:id） |
| 功能描述 | 系统在基础审批功能之上，增强加签、转交、退回、撤回等操作能力；审批表单清晰展示关键字段变化对比；支持备注说明、评论；支持流程待办提醒与催办。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 审批表单 | 表单组件 | 展示合同信息及关键字段变更对比（高亮变化字段） |
| 审批操作栏 | 操作按钮组 | 同意、拒绝、加签、转交、退回、撤回 |
| 备注输入框 | 文本域 | 审批时填写备注说明 |
| 评论区 | 评论组件 | 审批流程中的评论记录与新增评论 |
| 流程可视化 | 流程图组件 | 展示当前审批节点、已完成节点、待处理节点 |
| 待办提醒设置 | 配置控件 | 设置提醒方式（站内信/邮件）和提醒频率 |
| 催办按钮 | 操作按钮 | 向当前审批人发送催办通知 |

#### 二、功能详细说明

**1. 加签**
- 当前审批人可将其他人员加入当前审批节点（会签/或签）
- 加签人员完成审批后，流程继续向下流转
- 支持加签说明，记录加签原因

**2. 转交**
- 当前审批人可将审批任务转交给其他人员处理
- 转交后，原审批人不再参与该节点审批
- 需填写转交原因，系统记录转交操作日志

**3. 退回至任意节点**
- 当前审批人可将流程退回至已通过的任意历史节点
- 退回时选择目标节点，填写退回原因
- 目标节点审批人重新审批后，流程按原路径继续

**4. 撤回**
- 审批提交人可在审批完成前撤回申请
- 撤回后合同状态回退至「草稿」状态
- 需填写撤回原因，系统通知所有已审批人员

**5. 关键字段变化对比**
- 审批表单自动比对当前版本与上一版本的字段差异
- 变化字段高亮显示（如金额、服务内容、条款等）
- 支持展开「变更对比」面板查看详细差异

**6. 备注说明与评论**
- 每次审批操作均支持填写备注说明（必填/选填可配置）
- 评论区支持审批流程中所有参与人员发表评论
- 评论支持 @ 提及功能，被提及人员收到通知

**7. 待办提醒与催办**
- 系统自动向待审批人员发送待办提醒（站内信，可选邮件）
- 提醒频率可配置（每日一次 / 每 4 小时一次）
- 申请人或管理员可手动催办，向当前审批人发送催办通知
- 催办记录记入审计日志

#### 三、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 审批人打开审批详情页，查看合同信息及字段变更对比 |
| 2 | 审批人选择操作：同意 / 拒绝 / 加签 / 转交 / 退回 / 撤回 |
| 3 | 填写备注说明或退回/撤回原因 |
| 4 | 如需加签或转交，选择目标人员并确认 |
| 5 | 提交操作，系统记录日志并通知下一节点审批人 |
| 6 | 申请人或管理员可随时点击「催办」向当前审批人发送提醒 |

#### 四、技术约束

| 约束项 | 说明 |
|--------|------|
| API 接口 | `/api/approvals/:id/sign`（加签）；`/api/approvals/:id/transfer`（转交）；`/api/approvals/:id/return`（退回）；`/api/approvals/:id/withdraw`（撤回）；`/api/approvals/:id/urge`（催办） |
| 字段对比 | 基于合同版本历史，通过 `version_id` 关联比对 |
| 通知方式 | 站内信（实时）；邮件（可选，需配置 SMTP） |
| 权限要求 | 加签/转交/退回/撤回：当前审批节点处理人；催办：申请人或 `approval.manage` 权限 |
| 退回限制 | 仅可退回至已通过的节点，不可退回至未来节点 |
