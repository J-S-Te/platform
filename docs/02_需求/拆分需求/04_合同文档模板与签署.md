# 04 合同文档、模板与签署需求

## 1. 领域边界

合同正文、模板和签署台账属于合同业务域；文件对象、文件版本、访问控制和绑定关系由基础能力平台文件能力提供。文件字节可保存到受控本地/挂载目录，MySQL 只保存元数据、校验摘要和绑定关系。

## 2. 架构对齐后的补充要求

### 2.1 文件安全和元数据

- 每次上传创建 `FileObject` / `FileVersion`，并记录 SHA-256、大小、MIME、存储路径、访问控制、上传人和关联业务对象。
- 文件访问通过应用服务鉴权；禁止仅以静态文件路径作为访问凭证。
- 原始需求中的类型白名单、双扩展名检测、MIME 检测、内容扫描和路径清理保留，并增加下载/预览/删除审计。
- 文件上传目录为受控本地或挂载目录；禁止依赖 Redis 或对象存储作为本期强制条件。

### 2.2 模板和生成可追溯性

- 模板归合同模块管理，需保存版本、适用合同类型、占位符 Schema、启停状态和变更审计。
- 自动生成保存模板版本、字段快照、生成结果摘要和操作人；后续模板变更不能影响已生成合同。
- 生成引擎必须可重复、可解释；缺失字段应阻断生成。

### 2.3 签署与 OCR

- 电子签/回传服务通过适配器集成，不把第三方调用细节扩散到合同控制器。
- OCR 识别结果需要保存来源文件版本、提取字段、置信度、人工校验状态和校验人。
- 签署、回传、OCR、预览、下载均产生审计事件；高风险下载按权限和数据范围控制。

### CON-004 合同文档管理

| 功能编号 | CON-004 |
|---------|---------|
| 对应页面 | 合同详情页（文档标签页） |
| 功能描述 | 用户可为合同上传、预览、删除相关文档附件，支持版本管理和安全验证。 |

#### 一、页面元素

| 组件/控件 | 说明 |
|----------|------|
| 文档列表 | 展示文档名称、文件类型、文件大小、版本号、上传时间、上传人 |
| 上传文档按钮 | 触发文件上传操作 |
| 文件选择区域 | 支持点击选择或拖拽上传 |
| 文件类型提示 | 支持的格式列表展示 |
| 上传进度指示器 | 上传进度显示 |
| 文档预览链接 | 按文件类型返回不同格式内容 |
| 删除按钮 | 删除指定文档（含确认对话框） |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户查看合同的文档列表 |
| 2 | 用户上传文档文件（需 `contract.edit` 权限） |
| 3 | **系统安全验证**（详见技术约束） |
| 4 | 验证通过：系统记录文档名称、路径、大小、类型、版本、上传人，文件保存到 uploads 目录 |
| 5 | 用户点击预览查看文档内容（需 `contract.read` 权限） |
| 6 | 系统生成 5 分钟有效预览令牌，根据文件类型返回不同格式内容 |
| 7 | 用户删除文档（需 `contract.delete` 权限），弹出确认对话框 |

#### 三、安全验证流程（补充自 .md 文档）

| 验证步骤 | 说明 |
|---------|------|
| 1. 文件类型白名单验证 | 验证文件扩展名是否在允许的类型范围内 |
| 2. 双重扩展名检测 | 检测如 `test.php.jpg` 等双重扩展名攻击 |
| 3. 文件内容扫描 | 读取文件前 4KB 内容进行恶意代码扫描 |
| 4. MIME类型校验 | 验证文件 MIME 类型是否与扩展名匹配 |
| 5. 文件路径清理 | 防止路径遍历攻击 |

#### 四、文档预览支持格式

| 文件类型 | 预览方式 |
|---------|---------|
| PDF | 内联预览 |
| Word（.docx） | 文本提取展示 |
| 图片（.jpg/.png/.gif） | 直接展示 |
| 文本文件（.txt/.csv） | 内容展示 |

#### 五、技术约束

| 约束项 | 说明 |
|--------|------|
| 版本管理 | 支持文档版本号管理 |
| 文件存储 | 文件存储于服务器 uploads 目录 |
| 关联约束 | 文档与合同多对一关联 |
| 预览令牌 | 生成 5 分钟有效预览令牌（POST `/api/documents/:id/preview-token`） |
| 路径安全 | 文件路径清理防止路径遍历 |
| 访问权限 | 预览接口需 `contract.read` 权限 |

### CON-007 合同模板管理

| 功能编号 | CON-007 |
|---------|---------|
| 对应页面 | 合同模板管理页（/contract-templates） |
| 功能描述 | 管理员可上传 Word 文档（.docx）作为合同模板，并对模板进行分类、编辑、预览、启用/停用与删除管理。合同模板供 CON-008 合同自动生成功能调用，通过占位符填充关键字段自动生成合同全文。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 模板列表 | 数据表格 | 展示模板名称、分类、适用合同类型、版本、状态（启用/停用）、上传人、上传时间 |
| 上传模板按钮 | 操作按钮 | 触发上传 Word 文档（.docx），打开上传表单 |
| 模板上传表单 | 表单组件 | 含模板名称、分类、适用合同类型、Word 文件选择、模板说明 |
| 文件选择区域 | 文件上传 | 仅支持 .docx 格式，支持点击或拖拽上传 |
| 预览按钮 | 操作按钮 | 在线预览模板内容（文本提取展示） |
| 编辑按钮 | 操作按钮 | 编辑模板元信息（名称、分类、类型、说明），不支持在线编辑 Word 正文 |
| 启用/停用开关 | 开关控件 | 控制模板是否可供合同自动生成调用 |
| 删除按钮 | 操作按钮 | 删除模板（含确认对话框），已关联生成记录的模板不可删除 |
| 占位符说明区 | 文本展示 | 展示模板中可识别的占位符列表（如 {{甲方名称}}、{{合同金额}}），供配置参考 |

#### 二、模板占位符规范

合同模板使用双花括号占位符（`{{字段名}}`）标记需自动填充的关键字段，系统按字段名匹配合同录入信息。预置占位符如下：

| 占位符 | 对应字段 | 说明 |
|--------|---------|------|
| `{{合同标题}}` | 合同标题 | 用户输入 |
| `{{甲方名称}}` | 我方机构名称 | 取自系统配置 |
| `{{乙方名称}}` | 客户/供应商名称 | 取自 CUS-001 查询结果 |
| `{{合同金额}}` | 合同金额 | 用户输入，含货币类型 |
| `{{服务类型}}` | 服务类型 | 用户输入 |
| `{{系统名称}}` | 系统名称 | 选填 |
| `{{系统等级}}` | 系统等级 | 选填 |
| `{{付款条款}}` | 付款条款 | 用户输入 |

#### 三、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户（需 `contract_template.manage` 权限）进入合同模板管理页面 |
| 2 | 系统分页展示模板列表，标注启用/停用状态 |
| 3 | 用户点击「上传模板」，填写模板名称、分类、适用合同类型并选择 .docx 文件 |
| 4 | 系统对上传文件执行安全验证（详见技术约束），通过后解析 Word 文档内容，提取并展示识别到的占位符列表 |
| 5 | 用户确认模板信息无误，点击「保存」，模板存入 `contract_templates` 表，初始状态为"启用" |
| 6 | 用户可点击「预览」查看模板内容（文本提取）；点击「编辑」修改模板元信息 |
| 7 | 用户可通过启用/停用开关控制模板可用性；点击「删除」移除模板（已生成过合同的模板禁止删除） |

#### 四、技术约束

| 约束项 | 说明 |
|--------|------|
| 文件格式 | 仅支持 .docx（Word 2007+ OpenXML 格式）；不支持 .doc 旧格式，需先转换 |
| 文件大小 | 单文件 ≤ 10MB |
| 安全验证 | 复用 CON-004 文档安全验证流程（文件类型白名单、双重扩展名检测、内容扫描、MIME 校验、路径清理） |
| 模板解析 | 使用后端库（如 python-docx / docxjs）解析 .docx，提取正文文本与占位符 |
| 占位符识别 | 正则匹配 `{{字段名}}` 形式占位符，与预置字段白名单比对，未识别字段在预览时提示 |
| 存储 | 模板文件存于服务器 templates 目录（或对象存储），元信息存 `contract_templates` 表 |
| 权限要求 | `contract_template.manage`（模板上传/编辑/删除/启停）；`contract_template.read`（模板查看） |
| 版本管理 | 模板支持版本号管理，重新上传视为新版本 |
| 占位符约束 | 模板中必须至少包含一个预置占位符，否则上传时提示"模板不含可填充字段" |

### CON-008 合同自动生成

| 功能编号 | CON-008 |
|---------|---------|
| 对应页面 | 合同创建/编辑页（/contracts/new、/contracts/:id/edit） |
| 功能描述 | 用户在创建或编辑合同时，仅需录入合同必要关键信息（如编号、标题、客户、金额、服务类型、系统名称、系统等级、付款条款），选择已启用的合同模板后，系统调用该模板自动将占位符替换为关键信息，生成完整合同正文；用户可在此基础上手动微调后保存。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 模板选择下拉框 | 下拉选择 | 仅展示"启用"状态且适用当前合同类型的模板 |
| 关键信息录入区 | 表单组件 | 合同编号、标题、客户选择、合同类型、金额、货币类型、服务类型、系统名称（选填）、系统等级（选填）、付款条款等必要字段（与 CON-007 模板占位符对应的字段；其中系统名称、系统等级为选填） |
| 一键生成按钮 | 操作按钮 | 点击后调用所选模板，将关键信息填充至占位符，生成合同全文 |
| 合同正文预览区 | 富文本/文本区 | 展示根据模板生成的完整合同正文，支持手动编辑调整 |
| 生成状态提示 | 状态标签 | 展示生成状态：待生成 / 生成中 / 已生成 / 生成失败（占位符缺失） |
| 重新生成按钮 | 操作按钮 | 修改关键信息或切换模板后可重新生成 |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 用户（需 `contract.create` 权限）进入合同创建/编辑页 |
| 2 | 用户从模板选择下拉框中选择一个已启用模板（不选则走原手动录入正文流程） |
| 3 | 用户填写必要关键信息（编号、标题、客户、金额、服务类型、系统名称、系统等级、付款条款等，其中系统名称与系统等级为选填） |
| 4 | 用户点击「一键生成」，系统加载所选模板正文，将预置占位符替换为对应关键信息 |
| 5 | 系统校验占位符是否全部匹配：匹配成功则生成完整合同正文并展示在预览区；存在未匹配占位符则提示"以下字段未填写：XXX"，生成失败 |
| 6 | 用户在预览区对生成的合同正文进行必要微调（如补充模板未覆盖的个性化条款） |
| 7 | 用户点击「保存」，合同以"草稿"状态创建/更新，正文内容随合同一并保存 |

#### 三、技术约束

| 约束项 | 说明 |
|--------|------|
| 模板来源 | 仅调用 CON-007 中状态为"启用"的模板 |
| 字段映射 | 系统按 CON-007 占位符字段名自动匹配合同录入字段，各占位符来源如下：合同标题←标题；甲方名称←系统配置（我方机构名称）；乙方名称←CUS-001 查询结果（客户/供应商名称）；合同金额←金额（含货币类型）；服务类型←用户输入；系统名称←用户输入（选填）；系统等级←用户输入（选填）；付款条款←用户输入 |
| 占位符与合同实体关系 | 模板占位符（含服务类型/系统名称/系统等级）对应合同录入字段；合同实体本身的签订/开始/结束日期不属于模板占位符，仍按 CON-001 录入并存储，但不参与正文自动填充 |
| 生成引擎 | 后端基于模板正文做占位符替换（字符串模板引擎），不依赖外部大模型，确保生成结果可追溯、可控 |
| 占位符校验 | 生成前校验所有占位符均有对应值；缺失值阻断生成并提示用户补全 |
| 正文存储 | 生成的合同正文作为合同 `content` 字段存储，与模板解耦（后续编辑模板不影响已生成合同） |
| 权限要求 | `contract.create`（生成并保存合同）；`contract_template.read`（读取模板内容） |
| 兼容性 | 未选择模板时，合同正文由用户手动录入，与原 CON-001 流程完全兼容 |
| 审计记录 | 合同自动生成操作记录审计日志（所用模板、生成时间、操作人） |

### SIG-002 回传跟踪与 OCR 识别

| 功能编号 | SIG-002 |
|---------|---------|
| 对应页面 | 合同回传跟踪页（/contract/:id/tracking） |
| 功能描述 | 系统跟踪合同回传进度，超期未回传自动提醒催收；合同专员扫描上传回传件后，系统通过 OCR 自动识别印章、签名、日期，验证通过后状态变更为「已签署」。 |

#### 一、页面元素

| 组件/控件 | 类型 | 说明 |
|----------|------|------|
| 回传状态展示 | 状态标签 | 展示当前回传状态（待回传 / 已回传 / 已签署 / 逾期） |
| 逾期提醒记录 | 时间线组件 | 展示系统自动发送的催收提醒记录 |
| 上传回传件按钮 | 操作按钮 | 上传回传合同扫描件（PDF/图片） |
| OCR 识别结果展示 | 结果面板 | 展示 OCR 识别的印章、签名、日期信息及置信度 |
| 人工确认按钮 | 操作按钮 | OCR 识别通过后，专员人工确认，状态变更为「已签署」 |
| 催收提醒按钮 | 操作按钮 | 手动发送催收提醒通知 |

#### 二、操作步骤

| 步骤 | 操作说明 |
|------|----------|
| 1 | 合同状态为「已寄出」后，系统启动回传跟踪计时（默认 15 天） |
| 2 | 距寄出超过 15 天未回传：系统自动发送催收提醒通知销售人员 and 合同专员 |
| 3 | 合同专员收到回传件后，扫描上传至系统（支持 PDF 或图片格式） |
| 4 | 系统调用 OCR 服务自动识别：印章（是否存在、是否清晰）、签名（是否存在）、签署日期（是否填写） |
| 5 | OCR 识别通过（置信度 ≥ 85%）：系统提示「OCR 识别通过，请人工确认」 |
| 6 | 专员人工确认无误后，点击「确认签署」，合同状态变更为「已签署」 |
| 7 | 系统自动通知销售人员："合同已签署完成，状态已更新。" |

#### 三、OCR 识别规则

| 识别项 | 识别要求 | 处理方式 |
|--------|---------|---------|
| 印章识别 | 检测红色圆形印章图案，识别印章内文字 | 置信度 ≥ 85% 为通过；否则提示人工复核 |
| 签名识别 | 检测手写签名区域，确认存在签名笔迹 | 检测到签名区域即通过；否则提示人工复核 |
| 签署日期识别 | 识别日期格式文本（如"2026 年 07 月 05 日"） | 识别到有效日期即通过；日期缺失提示人工补填 |

#### 四、技术约束

| 约束项 | 说明 |
|--------|------|
| API 接口 | `/api/contracts/:id/upload-return`（上传回传件）；`/api/contracts/:id/ocr-verify`（OCR 识别）；`/api/contracts/:id/confirm-sign`（确认签署） |
| OCR 服务 | 对接第三方 OCR API（如腾讯云 OCR / 阿里云 OCR）或使用本地 OCR 引擎 |
| 逾期提醒 | 基于定时任务（Cron）每日检查，超期自动发送提醒 |
| 提醒通知模板 | "【逾期提醒】合同《{contract_title}》已寄出 {days} 天，尚未收到回传件，请及时跟进。" |
| 权限要求 | `contract.sign`（上传回传件、OCR 识别、确认签署）；`contract.view`（查看回传状态） |
| 回传文件存储 | 回传件存于 `contract_documents` 表，`doc_type` 标记为 `returned` |
