# 文件与异步任务开发说明

## 1. 模块边界

文件与异步任务模块遵循 Gin + GORM + MySQL，并使用本地受控目录保存文件内容，不使用 Redis、对象存储或 GORM `AutoMigrate`。

安全原则：

- 数据库只保存文件元数据和相对路径，不保存文件二进制；
- HTTP 响应不暴露物理路径；
- 本地 Store 拒绝路径穿越和符号链接逃逸，上传使用临时文件和原子发布；
- 下载按可信租户查询，并执行文件所有者或 `platform:file:download` 权限校验；
- 通用任务负载拒绝密码、Token、Secret、私钥等凭据字段；
- 清理、重试和重跑属于高风险操作，需要权限，其中清理、重试、重跑还需要 MFA 二次验证。

## 2. 已实现文件能力

- multipart 本地文件上传；
- 文件名清理、大小限制、扩展名/MIME/内容检测和允许列表；
- SHA-256、版本、所有者、分类、状态等元数据；
- 带租户边界和授权校验的文件下载；
- 按租户、截止时间和批次上限清理未绑定文件；
- 删除失败恢复状态、临时文件清理和安全摘要响应；
- 本地存储根目录由项目根 `.env` 的 `FILE_STORAGE_ROOT` 配置。

当前表结构没有单文件 `expires_at`，因此清理接口使用管理员提交的策略截止时间 `before`。这已经形成受控清理能力，但还不是“每个文件独立过期时间”的完整模型。

## 3. 已实现异步任务控制面

`JobService` 与 GORM Repository 已实现：

- 创建和分页查询 MySQL 任务；
- 按任务类型白名单、优先级、可用时间和陈旧锁恢复领取任务；
- 成功完成、可重试失败、退避和最大尝试次数；
- 取消排队或失败任务；
- 管理员将 `FAILED` / `DEAD` 任务重新入队；
- 从终态任务复制创建新的重跑任务；
- 运营列表不返回任务 Payload。

当前 `cmd/worker` 已运行审计导出和审计保留两个明确业务 Worker。通用 `JobService` 的调度状态机已经完成，但尚未注册任意业务任务执行器；在没有明确 `job_type`、Payload 契约和执行函数前，系统不会猜测或执行未知任务。

运行中任务的协作取消标记、重跑父子谱系字段尚未进入现有 `async_job` 表，因此当前取消只处理非运行状态，重跑通过保留原任务并创建新任务实现，但没有数据库父任务字段。

## 4. 已注册接口

| 方法 | 路径 | 权限 / 说明 |
| --- | --- | --- |
| `POST` | `/api/v1/files` | `platform:file:upload` |
| `GET` | `/api/v1/files/{file_id}/content` | `platform:file:download`，服务层仍执行租户与所有者校验 |
| `POST` | `/api/v1/files:cleanup` | `platform:file:cleanup` + MFA 二次验证 |
| `POST` | `/api/v1/async-jobs` | `platform:async-job:create` |
| `GET` | `/api/v1/async-jobs` | `platform:async-job:read` |
| `POST` | `/api/v1/async-jobs/{job_id}:cancel` | `platform:async-job:cancel` |
| `POST` | `/api/v1/async-jobs/{job_id}:retry` | `platform:async-job:retry` + MFA 二次验证 |
| `POST` | `/api/v1/async-jobs/{job_id}:rerun` | `platform:async-job:rerun` + MFA 二次验证 |

权限由 `000034_seed_platform_operations_permissions.sql` 初始化，OpenAPI 已同步。

## 5. 前端

`FileTaskOperationsModule.vue` 已挂载到 `PlatformConsoleView.vue`，提供文件上传、授权下载、清理和异步任务运营操作。组件不保存 Cookie、Token、文件物理路径或任务 Payload。

## 6. 后续明确缺口

只有在确认数据模型和执行契约后再继续开发：

1. `file_object.expires_at` 及按独立过期时间自动清理；
2. 通用 Worker 的任务类型注册表与具体业务执行器；
3. `async_job.cancel_requested_at` 支持运行中协作取消；
4. `async_job.rerun_of_job_id` 支持重跑谱系；
5. 多节点部署时本地文件共享或粘性路由方案。当前本地目录模式不具备天然跨实例文件共享能力。
