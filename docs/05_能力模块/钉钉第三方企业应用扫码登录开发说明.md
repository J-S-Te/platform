# 钉钉第三方企业应用扫码登录开发说明

> **状态**：已实现的对外接口与前后端联调契约。本文以当前 Gin 路由、GORM 状态存储、钉钉适配器和登录页调用链为准，规定钉钉第三方企业应用（ISV）内嵌二维码登录流程。它不把钉钉适配为 OIDC，也不改变本地账号密码、MySQL 会话、MFA、权限或审计的既有边界。
> **关联文档**：[平台接口规范](../03_接口规范/平台接口规范.yaml)、[接口文档](../03_接口规范/接口文档.md)、[数据模型文档](../03_接口规范/数据模型文档.md)、[JWT 文档](../03_接口规范/JWT文档.md)、[前后端接口契约](../03_接口规范/前后端接口契约.md)。

## 1. 提供商、配置与启用边界

- 提供商类型为 `DINGTALK_QR`；现有 `OIDC` 提供商仍按独立 OIDC 校验、发现与回调流程运行。
- `DINGTALK_QR` 当前管理 HTTP 配置使用 `client_id`、`client_secret`、`callback_uri`、`authorization_scopes`、显示名称与状态。第三方企业应用（ISV）内嵌二维码语义中，运行时 `client_id` 必须填写钉钉 `SuiteKey`，`client_secret` 对应 `SuiteSecret`/客户端密钥；`app_key` / `app_secret` 只保留为兼容性术语，不是当前 Gin 管理接口接受的 JSON 字段。不把这些字段当成 OIDC 的 `issuer` 或 JWKS 配置。
- `client_secret` 仅允许创建或更新时写入，使用 `IAM_FEDERATED_PROVIDER_SECRET_ENCRYPTION_KEY` 应用层加密保存。身份提供商读取接口、日志与审计只能显示 `client_secret_configured`，绝不返回 SuiteSecret/客户端密钥、授权码或上游令牌。
- 仅管理员预先绑定、绑定有效且租户、提供商、用户、账号均启用的本地身份可以登录。不得自动创建用户、账号、任职、角色或权限。
- 只有 `IAM_FEDERATED_PROVIDER_SECRET_ENCRYPTION_KEY` 与 `IAM_EXTERNAL_LOGIN_STATE_ENCRYPTION_KEY` 都非空时，启动装配才注册钉钉扫码路由。缺少任一配置时，钉钉适配器不启用；本地密码登录和现有 OIDC 登录不受影响。

## 2. 扫码会话与 MySQL 一次性状态

### 2.1 创建会话

匿名接口 `POST /api/v1/auth/dingtalk/qr-sessions` 接收：

```json
{
  "tenant_id": "01J...",
  "provider_code": "DINGTALK_QR",
  "return_to": "/"
}
```

- `return_to` 必须是本平台同源安全相对路径。运行时拒绝绝对 URL、`//` 网络路径、反斜杠、控制字符、片段、用户信息，以及原始或解码后会形成外部跳转的地址。
- 成功时返回 `201`，`data` 固定包含 `session_id`、`expires_at`、`render_mode:"dingtalk_frame"` 与 `sdk_config:{client_id,redirect_uri,response_type:"code",scope,state,prompt?}`。当前装配的 state 有效期为 **5 分钟**。
- 创建接口的稳定失败结果是：`422 PLATFORM_VALIDATION_ERROR`、`404 AUTH_DINGTALK_PROVIDER_NOT_AVAILABLE`、`500 PLATFORM_INTERNAL_ERROR`。
- 响应设置短时 HttpOnly 浏览器绑定 Cookie，Cookie 名为 `${AUTH_SESSION_COOKIE_NAME}_dingtalk_qr`，固定 `SameSite=Lax`。它不是平台会话 Cookie，不包含 state、授权码、SuiteSecret/客户端密钥、上游令牌、原始身份标识或平台 JWT。

### 2.2 状态保存与消费

- 表 `iam_dingtalk_qr_login_state` 由迁移 `000031_create_dingtalk_qr_login_state.sql` 创建，只保存 `state_hash`（SHA-256）和加密的 `payload_ciphertext`。原始 state、浏览器绑定值、授权码、SuiteSecret/客户端密钥、上游访问令牌和原始钉钉身份标识不入库。
- 加密载荷包含浏览器绑定哈希、会话 ID、提供商上下文、SuiteKey、回调地址和受限 `return_to`；不包含原始浏览器绑定值或 state。其加密密钥为 `IAM_EXTERNAL_LOGIN_STATE_ENCRYPTION_KEY`。
- 状态取值为 `ACTIVE`、`CONSUMED`、`EXPIRED`。回调用事务内的 `SELECT ... FOR UPDATE` 锁定记录；已过期的 `ACTIVE` 状态被改为 `EXPIRED` 并写入 `consumed_at`；正常消费改为 `CONSUMED` 并写入 `consumed_at`。
- 回调先验证浏览器绑定，再消费 state。绑定不匹配会拒绝当前请求但不消费 state；一旦绑定通过并消费，后续身份换取、预绑定检查、会话签发或 MFA 失败均不能重放该 state。

## 3. 内嵌二维码、回调与会话签发

1. 登录页以 `credentials: include` 创建扫码会话，并固定加载钉钉 **DTFrameLogin SDK**；不得让环境变量、接口数据或用户输入决定任意 SDK 脚本地址。
2. 前端仅使用返回的 `sdk_config` 渲染二维码，不得追加、删减、持久化或修改 `client_id`、`redirect_uri`、`response_type`、`scope`、`state`、`prompt`。
3. SDK 成功后，前端先比较 callback 中的 state 和本次 `sdk_config.state`，并校验 callback URL 与 `sdk_config.redirect_uri`；通过后由顶层页面导航到 `GET /api/v1/auth/dingtalk/callback`。二维码 iframe 不完成平台会话，也不通过跨窗口消息传递登录结果。
4. 回调优先读取 `authCode`，兼容读取 `code`；二者同时出现但不同则拒绝。`state`、授权码、上游 `error` 均不可写入日志、审计详情或跳转地址。
5. 服务端完成 state、浏览器绑定、有效期和一次性消费校验后，使用钉钉适配器换取并验证身份；以 `(tenant_id, provider_code, subject_hash)` 查找现有预绑定。原始 `unionId` 只在进程内立即哈希，不写入数据库、日志、审计详情、响应或 Cookie。
6. 回调一律以 `303 See Other` 完成：普通成功由既有会话签发逻辑创建真实服务端会话并写平台 HttpOnly Cookie；需要 MFA 时仅写既有预认证 Cookie，并跳转 `/login?dingtalk_mfa=1&return_to=...`，只有既有 MFA 验证成功后才创建会话。失败跳转 `/login?dingtalk_error=<稳定错误码>`。
7. 进入回调服务处理、执行 state 校验前，回调会清除扫码浏览器绑定 Cookie。方法不允许、查询过长或 `authCode`/`code` 冲突等早期拒绝直接 303，不依赖清除该 Cookie；Cookie 将在短时有效期后过期。

钉钉授权结果、授权码和上游令牌**不是平台 JWT**，也不是平台 Cookie 或前端可解析令牌。`Location`、JSON 响应、Cookie、日志和审计均不得包含这些协议敏感值、SuiteSecret/客户端密钥、原始 `unionId`、MFA 预认证凭据或平台 JWT。

## 4. 回调错误码与审计边界

| 情形 | 登录页稳定错误码 |
|---|---|
| 请求格式、上游拒绝、缺少授权码或 `authCode`/`code` 冲突 | `AUTH_DINGTALK_CALLBACK_INVALID` |
| state 缺失、失效、过期、重复消费或浏览器绑定无效 | `AUTH_DINGTALK_QR_SESSION_INVALID` |
| 钉钉身份换取或身份响应校验失败 | `AUTH_DINGTALK_IDENTITY_VERIFICATION_FAILED` |
| 未预绑定、解绑或本地身份不可用 | `AUTH_DINGTALK_EXTERNAL_IDENTITY_NOT_BOUND` |
| 提供商已停用或回调时不可用 | `AUTH_DINGTALK_PROVIDER_DISABLED` |
| 其他内部失败 | `PLATFORM_INTERNAL_ERROR` |
| 非 `GET` 回调请求 | `PLATFORM_METHOD_NOT_ALLOWED` |

- 会话创建在可取得 `tenant_id` 与 `provider_code` 时记录 `auth.dingtalk_qr_session.create`（`SYSTEM`、低风险）。
- 具有可信 tenant/provider 生命周期上下文的回调记录 `auth.dingtalk_qr_callback`（`SYSTEM`、高风险）；预绑定成功时另记录 `auth.dingtalk_qr_binding`（`USER`、中风险）。未绑定或上游拒绝归类为 `DENIED`，其他回调失败归类为 `FAILURE`。
- 缺少可信 tenant/provider 上下文的早期回调拒绝仅写安全运行日志，附带请求/链路关联信息和源 IP，不创建无法可靠归属租户的审计事件。
- 审计或安全日志不得记录 state、浏览器绑定值、授权码、SuiteSecret/客户端密钥、上游令牌、原始 `unionId`、会话 JWT 或 MFA 凭据。审计写入失败只记录服务端错误，不阻断回调登录处理。

## 5. 环境变量与验收

- 根目录 `.env` 仅使用 `IAM_FEDERATED_PROVIDER_SECRET_ENCRYPTION_KEY`、`IAM_EXTERNAL_LOGIN_STATE_ENCRYPTION_KEY` 与 `IAM_DINGTALK_HTTP_TIMEOUT` 支持钉钉运行时。钉钉 SuiteKey/SuiteSecret（管理兼容术语为 app_key/app_secret）必须经受控身份提供商接口的 `client_id`/`client_secret` 保存，不能放入 `.env`、前端构建变量或日志。
- `IAM_DINGTALK_HTTP_TIMEOUT` 必须大于 0 且不超过 1 分钟。生产 `callback_uri` 必须是已在钉钉开放平台登记的 HTTPS 地址。
- 验收至少覆盖：已预绑定普通账号签发会话；启用 MFA 的账号进入既有 MFA 流程；未绑定/解绑/停用账号/停用提供商拒绝；state 过期、重复消费、浏览器绑定不匹配拒绝；二维码失效后可刷新；响应、数据库、日志、审计和跳转地址不泄露敏感协议值。
- 真实钉钉扫码验收依赖在钉钉开放平台登记生产 HTTPS 回调地址以及可用的 ISV 应用凭据；不具备这些外部条件时，只能完成本地适配和模拟集成验证。
