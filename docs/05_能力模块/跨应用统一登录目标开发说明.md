# 跨应用统一登录目标开发说明

## 1. 目的与安全边界

跨应用统一登录目标用于登记平台本地登录成功后允许跳转的业务系统入口。它与 OAuth 2.0 / OIDC 的 `redirect_uri` 完全独立：

- `redirect_uri` 用于 OAuth/OIDC 授权码回调；
- `login_target_code` 用于平台会话创建或 MFA 完成后的业务落地；
- 浏览器不得提交 `target_uri`、`redirect_url` 或其他任意目标 URL；
- 目标只能由服务端按租户、应用、环境和目标编码精确查询；
- 当前只接受 HTTPS 绝对地址，拒绝用户信息、非 HTTPS 协议、空主机、控制字符和超长 URI；
- 目标不存在、停用或解析异常时安全回退到 `/`，不会采用调用方提供的地址。

实现遵循 Gin + GORM + MySQL，使用显式 SQL 迁移，不使用 Redis，不执行 `AutoMigrate`。

## 2. 数据模型与运行时解析

MySQL 表为 `platform_application_login_target`，由迁移 `000027_create_application_login_target.sql` 创建。

| 字段 | 作用 |
| --- | --- |
| `tenant_id`、`application_id`、`environment_id` | 完整租户与父级边界 |
| `target_code` | 登录请求使用的稳定编码，创建后不可修改 |
| `target_uri` | 管理员批准的 HTTPS 绝对地址 |
| `status` | 只有 `ACTIVE` 目标可解析 |
| `version` | 管理更新的乐观锁版本 |

运行时通过 `application.LoginTargetService.ResolveActiveTargetURI` 精确解析，并同时验证 Application、Environment 和 LoginTarget 的启用状态。`backend/internal/bootstrap/api.go` 已将解析服务注入本地认证 Handler。

本地密码登录请求可选携带以下三个顶层字段，必须全部出现或全部不出现：

```json
{
  "tenant_code": "default",
  "login_name": "admin",
  "password": "******",
  "application_id": "01J...",
  "environment_id": "01J...",
  "login_target_code": "contract-home"
}
```

认证使用服务端已确认的 `tenant_id` 解析目标，不能由请求覆盖租户。普通登录成功响应返回服务端批准的 `redirect_url`；需要 MFA 时，`202` 响应也携带同一批准地址，前端在 MFA 完成后继续使用该地址。前端只接受站内路径或服务端返回的 HTTPS 跨站地址。

当前目标三元组已接入本地密码登录和其 MFA 后续流程；标准 OIDC、外部 OIDC 与钉钉扫码登录仍各自使用已有服务端 state/回调边界，不接受动态外部 URL，也未宣称复用本登录目标参数。

## 3. 管理接口

以下接口已注册到共享 Gin 路由，并由会话认证、租户上下文、权限与审计中间件保护：

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/applications/{application_id}/environments/{environment_id}/login-targets` | `platform:application-login-target:read` | 分页查询，可按状态过滤 |
| `POST` | `/api/v1/applications/{application_id}/environments/{environment_id}/login-targets` | `platform:application-login-target:create` | 创建 HTTPS 白名单目标 |
| `GET` | `/api/v1/applications/{application_id}/environments/{environment_id}/login-targets/{login_target_id}` | `platform:application-login-target:read` | 查询单个目标 |
| `PATCH` | `/api/v1/applications/{application_id}/environments/{environment_id}/login-targets/{login_target_id}` | `platform:application-login-target:update` | 更新名称、URI、状态，必须提交版本号 |

创建示例：

```json
{
  "target_code": "contract-home",
  "name": "合同管理首页",
  "target_uri": "https://contract.example.com/workbench",
  "status": "ACTIVE"
}
```

同一环境内 `target_code` 与 `target_uri` 均保持唯一。版本不匹配返回冲突，客户端必须重新读取后再提交。

## 5. 验收要点

- 跨租户、跨应用或跨环境均无法读取、修改或解析目标；
- 非 HTTPS、带用户信息、协议相对、控制字符、空主机和超长地址会被拒绝；
- 登录请求不能通过 `target_uri`、`return_to`、`javascript:` 或相似域名绕过白名单；
- MFA 前后使用同一服务端批准的地址，响应不暴露内部账号身份元数据；
- 解析异常仅回退 `/`，不会跳转到请求方地址；
- OAuth/OIDC `redirect_uri` 模型和登录目标模型互不替代。
