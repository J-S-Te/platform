# 平台统一会话管理

平台通过 `AUTH_CENTRAL_SESSION_ENABLED` 统一管理浏览器生命周期。默认关闭；启用时
`AUTH_SESSION_TTL` 必须为 `8h`。空闲策略来自平台安全设置，当前目标为 1800 秒。
各 RP 只代理经过同源保护的真实活动，不以查询、令牌轮换或进入应用重设期限。

安全设置的保存端和前端输入均限制空闲窗口为 60–1800 秒，当前统一目标为 1800 秒，
避免保存执行器拒绝的更长窗口。启用前需只读核对既有 `sec_login_policy`：
若存在小于 60 或大于 1800 秒的历史记录，应先通过基础平台安全设置按版本保存并审计；
不直接改库或静默回填。无策略记录时采用平台正式默认值 1800 秒和版本 1。

平台受控部署向合同、项目、结算、CRM、客户门户、数析下发中央开关与公开桥接地址。
保留各自 Cookie、OIDC、角色与数据范围。Keycloak 的 Realm 和在线 Client 使用
28800 秒技术窗口；平台仍独立强制业务空闲与原始认证八小时上限。

旧会话不回填认证起点。升级后需要正常重新登录；缺绑定、到期、撤销及两个有效锚点
冲突均不能自动续命。原生直接授权请求执行 `prompt/max_age`；短效重新认证凭据仅能
用于原请求及新建的平台会话。PAR/JAR 内未承载的新鲜认证配置明确拒绝。
