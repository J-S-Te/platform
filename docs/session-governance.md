# 平台统一会话管理

平台通过 `AUTH_CENTRAL_SESSION_ENABLED` 统一管理浏览器生命周期。默认关闭；启用时
`AUTH_SESSION_TTL` 必须为 `8h`。空闲策略来自平台安全设置，当前目标为 1800 秒。
各 RP 只代理经过同源保护的真实活动，不以查询、令牌轮换或进入应用重设期限。

安全设置的保存端和前端输入均限制空闲窗口为 60–1800 秒，当前统一目标为 1800 秒，
避免保存执行器拒绝的更长窗口。启用前需只读核对既有 `sec_login_policy`：
若存在小于 60 或大于 1800 秒的历史记录，应先通过基础平台安全设置按版本保存并审计；
不直接改库或静默回填。无策略记录时采用平台正式默认值 1800 秒和版本 1。

平台受控部署向合同、项目、结算、CRM、客户门户、数析下发中央开关与公开桥接地址。
保留各自 Cookie、OIDC、角色与数据范围。Keycloak 的 Realm 和在线 Client 使用
28800 秒技术窗口；平台仍独立强制业务空闲与原始认证八小时上限。

旧会话不回填认证起点。升级后需要正常重新登录；缺绑定、到期、撤销及两个有效锚点
冲突均不能自动续命。原生直接授权请求执行 `prompt/max_age`；短效重新认证凭据仅能
用于原请求及新建的平台会话。PAR/JAR 内未承载的新鲜认证配置明确拒绝。

## 岗位模板修改后的在线授权刷新

岗位模板保存时，已有事务继续物化岗位绑定、推进应用授权修订号，并写入
`AUTHORIZATION_CHANGED` outbox。已登录用户不需要全局退出；前端在 F5、明确刷新
工作区或会话重载时，通过既有自描述接口请求当前角色、权限及数据范围。

协议使用 `X-Authorization-Refresh: 1`：RP 只在经过认证的 GET `/auth/me`、报销
`/auth/session`（保留各自公开前缀）解析该标记，并以内部请求上下文传给平台
GET `/oauth2/authorization-context`。它只要求新鲜读取，不承载主体、角色、租户或范围。
普通业务请求的同名标记不改变其权限，也不绕过身份、客户绑定或会话期限校验。

平台在线授权从当前数据库计算；Keycloak access token 用于可信身份及应用边界验证，
旧 token 中的角色不作为当前授权依据。强制读取绕过平台两秒短缓存并隔离迟到回填；
RP 同时绕过自己的授权 TTL 和陈旧读取兜底。有效角色变化更新原本地会话，不能以
授权读取推进真实交互时间或原绝对截止。中央模式仍先提交一次性令牌轮换材料，再在
独立事务复核权限；后续授权依赖失败不得回滚已消费的 refresh token。

RP 区分认证失效 401、授权撤销或冲突 403、依赖暂不可用 503；强制读取失败不返回
旧权限成功。平台解析器自身的非授权故障保留既有 5xx 协议，由 RP 映射依赖错误。
必要的本应用会话安全失效不等同于平台或 Keycloak 全局注销；全撤销后再次授予时，
部分 RP 可能需要重新建立本地会话，仍由现有 SSO 流程处理。CRM 与客户门户支持
清空授权投影后沿用原 Cookie 恢复；门户每次重核客户映射及商业能力交集。

Keycloak 继续异步按最新平台快照删除旧 Client 角色并授予新角色，保留既有重试、
死信和授权有效期对账。页面得到最新在线授权不代表 Keycloak 投影已同步成功；
故障应通过现有 outbox/worker 运维入口排查，不通过全局登出或改 JWKS 缓存解决。

发布顺序为平台与 RP 后端先就绪，再发布前端；旧调用方不带标记时保持原缓存语义。
无新增数据库迁移、依赖或权限码。验证应先覆盖一个隔离账号和应用的授权缩小、
撤销、依赖失败和迟到响应，再做原 Cookie 下的 F5。单元、HTTP 测试替身或本地浏览器
夹具不能替代真实 MySQL 跨实例行锁及真实 Keycloak/SSO 验收。
