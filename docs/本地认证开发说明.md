# 本地认证开发与联调

## 已实现范围

当前认证模块提供以下 API：

- `POST /api/v1/auth/login`：仅接受 `login_type=password`，校验本地账号的 Argon2id 密码凭据，创建 `iam_session` 并下发 HttpOnly JWT Cookie。
- `POST /api/v1/auth/token/refresh`：在有效 Cookie、会话、账号、用户和租户均有效时续期会话并替换 Cookie。
- `POST /api/v1/auth/logout`：撤销当前会话并清理 Cookie。
- `GET /api/v1/auth/me`：返回当前租户、用户、账号，以及 `platform` 应用下生效的用户角色和 `ALLOW` 权限摘要。
- `POST /api/v1/auth/password:change`：当前登录主体校验旧密码后设置新强密码，撤销该账号所有有效会话并清理当前 Cookie。
- `POST /api/v1/accounts`：为既有用户创建 `HUMAN/LOCAL` 本地登录账号及强初始密码。
- `POST /api/v1/accounts/{account_id}/password:initialize`：仅为尚未拥有密码凭据的账号初始化强密码。
- `POST /api/v1/accounts/{account_id}/password:reset`：管理员重置密码；服务端生成的临时强密码只在当前成功响应中返回一次。

所有浏览器 API 调用必须携带 `credentials: 'include'`，JWT 不会出现在响应体或前端存储中。

## 准备本地密钥

项目根目录 `.env` 使用文件路径引用 JWT 密钥，不保存私钥内容。首次运行可从项目根目录执行：

```bash
make -C backend generate-dev-jwt-keys
```

该命令会生成：

- `backend/data/keys/jwt-ed25519-private.pem`：PKCS#8 Ed25519 私钥，权限为 `0600`。
- `backend/data/keys/jwt-ed25519-public.pem`：PKIX Ed25519 公钥。

根目录 `.env` 与 `.env.example` 中的 `AUTH_JWT_PRIVATE_KEY_PATH`、`AUTH_JWT_PUBLIC_KEY_PATH` 已指向上述开发路径。相对路径以所选 `.env` 文件所在目录解析；后端从 `backend/` 启动时会回退读取根目录 `.env`。生产环境必须由部署系统通过环境变量或受控挂载提供不同的密钥文件。

## 联调前置条件

1. 配置 MySQL 后，从项目根目录执行 `make -C backend migrate`。
2. 生成或配置 JWT 密钥。
3. 首次本地部署时，在根目录 `.env` 配置至少 32 字符的随机 `IAM_BOOTSTRAP_TOKEN`，调用受控初始化接口创建首个管理员。
4. 初始化成功后清空 `IAM_BOOTSTRAP_TOKEN` 并重启 API；随后使用创建的账号登录。

迁移初始数据**不会**创建固定密码或默认人类账号。首个管理员只能通过下述一次性受控接口创建；后续常规账号由具备相应权限的管理员使用账号生命周期接口创建、初始化或重置密码。

## 初始化首个超级管理员

该接口没有前端页面，也不使用 Cookie 会话，仅允许部署管理员在首次部署时调用：

```bash
export IAM_BOOTSTRAP_TOKEN=请从根目录.env读取的至少32字符随机值
curl -X POST http://localhost:8080/api/v1/iam/bootstrap/first-super-admin \
  -H "Content-Type: application/json" \
  -H "X-Bootstrap-Token: ${IAM_BOOTSTRAP_TOKEN}" \
  --data '{"display_name":"平台超级管理员","account_name":"admin","password":"请使用至少12位的真实强密码"}'
```

接口以 5 次/分钟限流；令牌仅在内存中保存 SHA-256 摘要并进行常量时间比较。它在一个 GORM 事务内创建用户、`LOCAL` 人类账号、Argon2id 凭据、`platform-super-admin` 角色绑定和 `iam_bootstrap_state` 标记。成功后必须立即清空根目录 `.env` 的 `IAM_BOOTSTRAP_TOKEN` 并重启 API；令牌为空时该接口返回 `404`。不得将令牌或密码提交给前端、写入脚本仓库、日志或审计摘要。

## 密码凭据存储约定

`iam_password_credential` 的 `password_hash` 存储原始 Argon2id 派生字节；`hash_algorithm` 固定为 `argon2id`；`algorithm_params` 存储如下 JSON：

```json
{
  "version": 19,
  "memory_kib": 65536,
  "iterations": 3,
  "parallelism": 2,
  "salt_base64": "...",
  "key_length": 32
}
```

后续 IAM 密码设置用例必须使用此约定，并使用 `internal/shared/security.HashPassword` 生成摘要和元数据；不得把明文密码写入数据库、日志、审计摘要或浏览器存储。

## 常规账号与密码生命周期

- 创建本地账号需要 `platform:account:create` 权限。请求中的 `initial_password` 必须为 12 至 128 个 Unicode 字符，且同时包含大写字母、小写字母、数字和符号，不能包含空白字符。
- 密码初始化需要 `platform:account:password-initialize` 权限，仅允许没有密码凭据的 `ACTIVE HUMAN/LOCAL` 账号执行；成功后会撤销该账号全部有效会话。
- 管理员重置需要 `platform:account:password-reset` 权限及当前 `version`。服务端用加密安全随机数生成 24 位强密码，`temporary_password` **仅**出现在本次成功响应；管理员必须立即复制，并通过线下安全渠道交付给对应人员。临时密码不会写入日志、审计、缓存或数据库，也不得保存到浏览器持久化存储；未及时保存只能再次重置，下一次会生成不同密码。
- 管理员重置成功后会撤销全部有效会话，**不会**解除 `LOCKED` 账号；解锁仍应调用登录安全模块的管理员解锁接口。
- 当前用户修改密码必须提交 `current_password` 和满足同一强度规则的 `new_password`。成功后清理当前 Cookie 并撤销该账号全部有效会话，用户必须重新登录。

## 当前边界

OIDC Authorization Code + PKCE、Refresh Token、撤销、Discovery、JWKS、UserInfo、RP-initiated Logout、`private_key_jwt`、PAR/JAR 与独立 post-logout URI 注册均已实现。TOTP MFA 已接入密码登录、外部登录及高风险操作二次验证；标准 OIDC 外部身份登录和钉钉 `DINGTALK_QR` 预绑定扫码登录已接入既有 MySQL 会话与审计链路。用户授权同意的后端查询、授权和撤回接口已经提供，Vue 独立同意页仍待实现；服务账号令牌、审计事件接收/查询由对应模块提供。
