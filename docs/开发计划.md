# 基础能力平台后端结构模型与文档蓝图

## 总结
本文记录基础能力平台早期的后端蓝图与 OpenAPI 3.1 草案交付。既有 `docs/系统架构.md`、`docs/核心模型与MySQL设计.md`、`docs/平台接入说明.md` 保持为架构与模型的权威来源；当前已落地代码的 Gin + GORM 迁移要求与验证记录以 `docs/Gin与GORM迁移计划.md` 为准。

## 文档交付
- 新增 `docs/后端实施说明.md`：定义 Go 模块化单体目录、模块边界、依赖方向、请求中间件链、Gin + GORM + MySQL Driver 的实现基线、事务/异步任务边界，以及与当前前端页面的能力映射。
- 新增 `docs/后端模型映射.md`：将前端的用户、账号、组织任职、角色、角色绑定、权限、审计、平台设置、安全与可观测页面，映射到 MySQL P0 表、P1 预留模型、状态码、权限点和数据脱敏规则。
- 新增 `docs/前后端接口契约.md`：定义前端从 mock 数据切换到 API 的调用约定、分页/筛选格式、统一错误响应、Cookie 会话行为，以及未实现 P1 页面如何返回能力状态。
- 新增 `api/openapi/平台接口规范.yaml`：提供 OpenAPI 3.1 草案，覆盖 P0 可实现接口与 P1 前端契约接口。

## 后端模型与接口决策
- 采用模块化单体：`tenant`、`applicationregistry`、`identity`、`organization`、`authorization`、`security`、`audit`、`configuration`、`observability`、`notification`、`dictionary`、`shared`、`transport/http`；模块仅通过公开 application contract 或应用内事件协作。
- 持久化严格遵循现有 MySQL 规范：ULID、UTC `DATETIME(3)`、`tenant_id` 隔离、聚合根 `version` 乐观锁、稳定英文状态码、审计分区表无外键；不使用 Redis，文件仍为本地受控目录方案。
- 当前已落模型：应用/环境/客户端、租户、用户、账号、密码凭据、首个超级管理员初始化状态、组织/岗位/任职、会话、资源/权限/角色/角色权限/角色绑定/策略版本、审计去重/审计事件、配置命名空间/条目/发布、平台基础设置、通知设置、业务字典/字典项、文件元数据与异步任务、登录策略/登录失败记录/风险事件。
- 控制台认证使用 `POST /api/v1/auth/login` 校验账号密码后签发 **JWT Cookie**；JWT 包含会话、租户、用户、账号和过期信息，`iam_session` 保存会话状态、撤销状态与到期时间。Cookie 固定为 `HttpOnly`、`Secure`、`SameSite=Lax`，前端仅以 `credentials: include` 调用接口，不保存 token。首次部署可由受控运维流程调用 `POST /api/v1/iam/bootstrap/first-super-admin`：接口仅在根目录 `.env` 配置至少 32 字符的 `IAM_BOOTSTRAP_TOKEN` 时开放，使用常量时间比较和单个 GORM 事务创建本地首个超级管理员与 `iam_bootstrap_state` 标记；它不提供前端页面，成功后必须清空令牌并重启服务。首个管理员完成初始化后，已实现常规本地账号创建、密码初始化、管理员重置及当前用户改密；管理员重置生成的强临时密码只在本次成功响应中返回，必须复制后线下交付，禁止记录、审计或持久化。
- OIDC/OAuth 运行时已覆盖 `GET /authorize`、Authorization Code、PKCE（`S256`/`plain`）、Refresh Token 轮换与复用检测、RFC 7009 Revoke、Discovery、JWKS、UserInfo、Logout / 独立 Post Logout Redirect URI、`private_key_jwt`、PAR 与签名 JAR。状态由 `000019_create_oidc_protocol.sql` 和 `000020_create_identity_enhancements.sql` 显式迁移持久化；授权码、刷新令牌、客户端断言 `jti` 与 PAR 请求均不保存明文。P7 的 Application、Environment、OAuth Client、Scope、精确回调地址、独立登出后回调地址、客户端公钥和客户端凭据受控管理均为协议前置配置。
- P7 已实现应用 Bearer 保护的审计单条/批量上报、MySQL `async_job` 驱动的本地 CSV 导出 Worker、受租户和权限保护的下载接口，以及成功登录/退出的最佳努力审计。当前实现会对已识别账号的认证失败和锁定写入生命周期审计；未知账号失败不关联账户身份。
- 审计事件后端仍按既有规范保留 `subject`、`request_id`、`trace_id` 等内部字段；当前前端列表、详情和导出 DTO 不返回这些已移除字段。审计只提供查询、详情和导出，不提供直接删除接口；归档/清理由受控保留任务完成并产生新的审计事件。
- 当前“审计上报重试”页面只定义平台接收侧状态和平台死信重放能力，不允许平台直接操作业务系统本地 `audit_outbox`。
- 运行日志、Trace、Metric 不写入 MySQL；当前由进程内有界存储采集查询并写入本地 JSON 文件，告警规则和执行结果写入 MySQL。通知偏好保留历史兼容字段；实际通知只实现站内信模板、消息投递、收件箱与失败重试，不提供邮件、短信、SMTP 或 Webhook 发送。业务字典已实现租户隔离、启停和运行时启用项读取。

## OpenAPI 覆盖范围
- P0：首次超级管理员受控初始化；登录/刷新/退出/当前会话/当前用户改密；用户、常规本地账号创建、密码初始化与管理员重置、组织、岗位、任职；资源、权限、角色、角色绑定；授权单次与批量判定；审计事件接收、批量接收、分页查询、详情与导出任务；配置命名空间、条目、发布与读取；平台基础设置、站内信通知偏好、业务字典及字典项。
- 已落地身份增强接口：外部身份提供商本地配置与用户绑定、TOTP 注册/恢复码/挑战验证、浏览器会话的同意查询/授予/撤销、客户端公钥和独立登出后回调地址管理。外部身份的第三方协议回调与断言验签适配、Vue 同意页、审计归档、告警规则和可观测性配置仍需继续开发。密码登录 MFA 强制校验与高风险操作二次验证已通过预认证和会话绑定的一次性授权落地。
- 统一采用 `/api/v1`、`page`/`page_size`、`keyword`、`filter[...]`、稳定错误码与 `{ code, message, request_id, details }` 错误响应格式；写操作明确要求权限点、审计事件和乐观锁版本。

## 验证标准
- 新文档中的表、模块、API 与现有 `docs/` P0/P1 分层无冲突。
- 每个现有前端页面/操作均能在前后端契约文档中找到对应 API、权限、模型归属或明确的 P1 占位状态。
- OpenAPI 3.1 文件可通过语法校验；所有 P0 写接口声明鉴权、租户上下文、错误响应和审计要求。
- 审计接口中不存在直接删除事件的端点；前端已隐藏的主体、Request ID、Trace ID 不出现在列表、详情和导出响应 DTO 中。

## 默认假设
- 本文最初阶段只交付模型和文档；后续实现已按独立迁移计划推进，不以本文的历史交付边界限制现有代码。
- 当前实现统一采用 Go、Gin、GORM、MySQL 和 JWT Cookie 会话；密码凭据使用 Argon2id 存储。
- 当前仅存在默认租户，但所有模型和 API 从第一版保留租户上下文与隔离字段。
