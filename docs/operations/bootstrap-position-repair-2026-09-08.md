# 首次管理员初始化失败：默认岗位被迁移停用

## 原因与修复

000047 创建固定超级管理员岗位，000066 停用未被引用的默认岗位。全新数据库在管理员初始化前没有任职记录，因此岗位被停用，而初始化仓储要求其状态为 ACTIVE。

新增 000103 修复迁移，不修改历史迁移及校验和。仅恢复默认 ACTIVE 租户、ACTIVE ROOT 组织下固定 ID/code 的 DISABLED 引导岗位，并要求该租户尚无 iam_bootstrap_state。不会恢复其他默认业务岗位、已删除/改码岗位，或覆盖已初始化租户的岗位停用决定。

初始化仍使用租户行锁、事务和一次性状态校验；未放宽密码策略或授权规则。缺失可用岗位时错误现在明确指向岗位及迁移检查。

## 本地恢复

使用包含本修复的工作区，在 platform 目录重新执行原本的启动命令，例如 `bash scripts/docker-local.sh up`，保留此前使用的自定义环境文件参数。脚本先构建镜像、执行迁移，再提示首次管理员初始化。已有迁移安全跳过，新增 000103 自动执行。不要删除数据卷，也不要直接修改已执行的 000066。

密码在交互提示中输入，不放入聊天或命令参数。已初始化环境不会因本迁移重新创建管理员。

## 回归验证

`migrations/bootstrap_mysql_integration_test.go` 使用 PLATFORM_BOOTSTRAP_TEST_DSN 指向独立、空的一次性 MySQL 数据库；非空数据库直接拒绝执行。测试覆盖历史完整迁移链故障复现、失败无用户残留、追加修复成功、迁移重跑、SQL 重放幂等、其他五个业务岗位保持停用、真实 BootstrapService 创建账号/任职/初始化状态、重复初始化拒绝及已初始化租户停用岗位不被恢复。

未设置测试 DSN 时该集成测试会明确跳过；普通单元测试不能替代这项验证。

2026-09-08 已使用独立 MySQL 8.4 实际执行该测试，通过；平台 `go test -count=1 ./...`、`go build ./...`、`go vet ./...` 和 `git diff --check` 均返回 0。构建有沙箱禁止模块元数据缓存写入的非致命警告。测试未使用或改动业务数据库；实际本地启动及管理员交互输入仍由操作者执行。
