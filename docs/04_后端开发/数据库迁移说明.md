# MySQL 迁移说明

- 迁移文件按 `000001_描述.sql` 连续编号；**已经在任何环境执行过的文件不得修改**，后续变更必须新增迁移文件。
- 从项目根目录运行 `make -C backend migrate`，或进入 `backend/` 后运行 `go run ./cmd/migrate`。命令默认读取项目根目录 `.env` 中的 MySQL 配置；从 `backend/` 运行时会自动回退到父目录，也可用 `ENV_FILE` 指定其他环境文件。
- `platform_schema_migration` 记录版本、文件名、SHA-256 校验和与执行时间；同一版本的文件内容被修改时，迁移会拒绝继续执行。
- 迁移执行期间使用 MySQL `GET_LOCK` 避免并发改表。由于 MySQL DDL 可隐式提交，每条语句独立执行；SQL 需保持可安全重试。
- `000011_seed_platform_defaults.sql` 只创建默认租户、平台应用、开发环境、根组织、P0 权限、内建角色和 `platform.console` 配置命名空间。它**不会**创建带默认密码的管理员账号；首个管理员应在身份认证模块中使用 Argon2id 密码摘要显式创建。
- `000018_add_application_registry_management_permissions.sql` 为 Application、Environment、OAuth Client 及客户端密钥受控管理补充资源、权限和内建角色授权；表结构沿用既有应用注册迁移，未使用 `AutoMigrate`。
- `000019_create_oidc_protocol.sql` 创建 OIDC/OAuth 运行时的授权码、刷新令牌族、刷新令牌和令牌撤销表；机密只保存 SHA-256 摘要，刷新令牌族以 `scope` 和 `authorized_at` 固化原授权范围，所有协议时间均使用 UTC `DATETIME(3)`。
