# 前端页面与后端模型映射

## 1. 接口通用约定

- 根路径：`/api/v1`；JSON 使用 `snake_case`；时间使用 RFC 3339 UTC 字符串；主键使用 ULID。
- 成功响应：`{ "code": "OK", "message": "...", "request_id": "...", "data": {} }`。
- 列表响应：`data.items`、`data.page`、`data.page_size`、`data.total`。
- 失败响应：`{ "code": "AUTH_PERMISSION_DENIED", "message": "无权执行此操作", "request_id": "...", "details": {} }`。
- 未实现的 P1 能力返回 `501` 与 `PLATFORM_CAPABILITY_NOT_ENABLED`，不得以 mock 成功响应掩盖未启用能力。

## 2. IAM 与授权

| 前端实体/动作 | 后端资源 | 表/聚合 | 权限示例 |
|---|---|---|---|
| 用户列表、详情、新增、编辑、启停 | `/users` | `iam_user` | `platform:user:view/manage` |
| 登录账号、账号状态 | `/accounts` | `iam_account`、`iam_password_credential` | `platform:account:view/manage` |
| 组织、岗位、任职 | `/org-units`、`/positions`、`/memberships` | `iam_org_unit`、`iam_position`、`iam_membership` | `platform:organization:view/manage` |
| 角色与权限集合 | `/roles` | `authz_role`、`authz_role_permission` | `platform:role:view/manage` |
| 角色绑定 | `/role-bindings` | `authz_role_binding` | `platform:role-binding:view/manage` |
| 权限注册 | `/resources`、`/permissions` | `authz_resource`、`authz_permission` | `platform:permission:view/manage` |

账号、用户、任职、角色绑定是不同模型；账号禁用不删除用户，任职结束不删除历史记录。所有更新请求携带 `version`，后端使用乐观锁。

首次部署的首个超级管理员不属于控制台用户管理操作：`POST /iam/bootstrap/first-super-admin` 仅通过根目录 `.env` 的 `IAM_BOOTSTRAP_TOKEN` 和请求头 `X-Bootstrap-Token` 受控执行。它不使用 Cookie 会话、不提供前端页面，成功后写入 `iam_bootstrap_state` 并应清空令牌、重启服务。常规本地账号和密码生命周期由 `POST /accounts`、`POST /accounts/{account_id}/password:initialize`、`POST /accounts/{account_id}/password:reset` 及 `POST /auth/password:change` 提供；请求密码遵循强密码规则，管理员重置的临时密码只在当前成功响应中返回一次，必须线下交付且不得进入日志、审计或持久化存储。

### 2.2 钉钉第三方企业应用扫码登录

| 前端区域 | API / 服务契约 | 模型 / 安全边界 | 状态 |
|---|---|---|---|
| 登录页“钉钉扫码登录”入口 | `POST /auth/dingtalk/qr-sessions` | `iam_dingtalk_qr_login_state`（迁移 `000031`）：仅保存 state 摘要、加密载荷、过期和受控 `return_to`；返回 `session_id`、`expires_at`、`render_mode: dingtalk_frame` 及仅给发起浏览器的 `sdk_config` | 按新版扫码契约对齐；不返回旧式授权地址字段或密钥 |
| 钉钉授权回调 | `GET /auth/dingtalk/callback` | 服务端校验 state 摘要、固定 SameSite=Lax 浏览器绑定、过期/一次性消费及钉钉身份；按外部身份哈希查询预绑定用户；普通账号复用 `iam_session`，MFA 账号复用预认证流程 | 始终 303：成功到受限 `return_to`，MFA 到登录页，失败到稳定错误码；不返回 HTML 或跨窗口消息桥接内容 |
| 外部提供商管理 | `/identity-providers` | `iam_identity_provider`：`DINGTALK_QR` 保存 SuiteKey、加密 SuiteSecret/客户端密钥、HTTPS 回调地址和权限配置；响应仅显示 `app_secret_configured` | 接口契约已扩展 |
| 外部身份预绑定 | `/users/{user_id}/external-identities` | 只保存不可逆外部身份哈希；不自动创建本地用户、账号、组织、任职、角色或权限 | 管理控制面 |

前端二维码仅在顶层登录页发起与完成；内嵌容器仅供官方 DTFrameLogin SDK 渲染。SDK 成功后必须先校验 state 与 redirect URL，再由顶层页面导航后端 callback。不得将 state、授权码、钉钉令牌或原始身份标识写入 LocalStorage、SessionStorage、URL、日志或埋点；原始 `unionId` 不存不记。详情见 `钉钉第三方企业应用扫码登录开发说明.md`。

## 3. 审计日志

### 3.1 查询 DTO

当前控制台允许展示：`id`、`occurred_at`、`operator_display_name`、`action_type`、`application_name`、`environment_code`、`resource_display_name`、`resource_type`、`method`、`path`、`client_ip`、`status_code`、`result`、`risk_level`、`detail`、`change_summary`。

当前控制台不展示且导出 DTO 不返回：`subject`、`request_id`、`trace_id`。这些字段仍按审计规范保存在内部模型，供受限排障和跨系统关联使用。

### 3.2 约束

- 审计列表支持 `keyword`、应用、环境、动作类型、风险、结果和时间范围筛选。
- 审计事件只读；没有 `DELETE /audit/events/{id}` 或批量删除接口。
- 导出通过 `POST /audit/export-jobs` 创建 `async_job`，随后查询任务状态/下载地址；不得在同步请求直接生成大文件。
- 审计写入 API 要求稳定 `event_id` 并以 `audit_event_dedup` 幂等。

## 4. 设置、登录安全与 P1 预留

| 前端页签 | 接口模型 | 状态 |
|---|---|---|
| 配置中心基础设置 | 配置命名空间 `platform.console`，条目/发布模型 | 已实现 |
| 平台基础设置 | `platform_setting`：机构名称、机构简称、时区、资质信息 | 已实现 |
| 通知设置 | `notification_setting`：保留站内信偏好；邮件字段为历史兼容，不提供邮件发送 | 已实现 |
| 字典管理 | `dict_dictionary`、`dict_item`：字典及字典项的启停和运行时查询 | 已实现 |
| 登录安全与风险控制 | `sec_login_policy`、`sec_login_attempt`、`sec_risk_event`、`iam_account.locked_until`、`iam_password_credential` | 已实现 |
| MFA 登录与高风险二次验证 | `sec_mfa_factor`、`iam_mfa_login_pre_auth`、`sec_mfa_step_up_grant`：TOTP/恢复码、一次性登录预认证、会话绑定的单次授权 | 已实现 |
| 审计投递 | 平台接收侧投递统计/死信重放 | P1 |
| 可观测性 | `obs_service`、`obs_log_policy`、`obs_alert_rule` | P1 |

平台基础设置、通知设置和业务字典均按当前 Cookie 会话确定租户，前端不得提交 `tenant_id` 或审计字段。设置读取在租户尚未保存记录时返回默认值；更新时必须提交 `version`，写入后生成首个版本。通知偏好仍由 `notification_setting` 保存；实际站内信由 `notification_template`、`notification_template_version`、`notification_message` 与 `notification_delivery` 独立建模，支持模板、渲染、收件箱投递、已读和失败重试。平台不提供邮件、短信、SMTP 或 Webhook 发送能力。运行时按字典编码读取时，只返回启用字典下的启用字典项，结果按 `sort_order` 排序。

登录安全已支持按租户维护失败次数阈值、锁定时长和失败记录重置窗口；认证失败会写入 MySQL、达到阈值会锁定账号，管理员可解锁并查询、处置风险事件。登录入口当前采用单体进程内固定窗口限流（30 次/分钟）；多实例部署前必须另行评审共享限流介质，不得假定现有进程内计数可跨实例生效。MFA 已支持密码登录预认证和高风险操作二次验证：启用 MFA 的账号必须先完成 TOTP/恢复码验证才会创建会话；高风险接口要求消费绑定当前会话、最长两分钟且仅一次有效的授权。可配置的 IP/网络策略及失败关闭等增强能力仍归入 P1。平台通过进程内有界存储采集并查询运行日志、Trace 和 Metric，同时将采集结果写入本地 JSON 文件；告警规则和执行结果使用 MySQL。该实现不等同于跨实例集中式 Telemetry 或 OTLP 后端，多实例场景仍需后续引入统一采集与查询基础设施。

## 5. 前端调用说明

- 前端请求必须发送 `Accept: application/json`；有请求体时发送 `Content-Type: application/json`。
- 认证后所有请求使用 `credentials: 'include'`；不得从 LocalStorage 读取或写入 JWT。
- `401` 表示会话失效，前端跳转登录；`403` 表示权限拒绝；`409` 表示版本冲突，提示刷新；`429` 表示限流；`501` 表示 P1 能力尚未启用。
- 前端在替换 mock 数据前，必须将响应中的 UTC 时间按页面时区格式化，不得修改后端原始时间。
