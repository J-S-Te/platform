# IAM 用户、账号与组织管理本地开发说明

## 已实现接口

所有接口位于 `/api/v1`，均需要已登录的 `bp_session` Cookie：

- 用户：`GET/POST /users`、`GET/PATCH /users/{user_id}`
- 账号：`GET/POST /accounts`、`PATCH /accounts/{account_id}`、`POST /accounts/{account_id}/password:initialize`、`POST /accounts/{account_id}/password:reset`
- 当前账号密码：`POST /auth/password:change`
- 组织：`GET/POST /org-units`
- 岗位：`GET/POST /positions`
- 任职：`GET/POST /memberships`、`PATCH /memberships/{membership_id}`

列表响应统一为 `data.items`、`data.page`、`data.page_size`、`data.total`。用户、账号和任职的分页参数为 `page`、`page_size`、`keyword`、`filter[status]`；组织和岗位接口依据当前 OpenAPI 契约使用固定的第 1 页、每页 100 条，并仍返回同一分页响应结构。

## 手机号保护

`POST /users` 和 `PATCH /users/{user_id}` 中的 `mobile` 是可选敏感字段。服务端仅保存 AES-256-GCM 密文以及用于精确检索的 HMAC-SHA-256 摘要，响应中只返回 `mobile_masked`。

若要提交 `mobile`，在项目根目录 `.env` 中配置一个 Base64 编码的 32 字节密钥：

```dotenv
IAM_MOBILE_ENCRYPTION_KEY=<base64-encoded-32-byte-key>
```

本地可使用下列命令生成后粘贴到根目录 `.env`；密钥不能提交到 Git：

```bash
openssl rand -base64 32
```

未配置该变量时，服务可以正常启动和管理不含手机号的用户；携带 `mobile` 的写请求会失败，避免敏感信息以明文落库。

## 边界与后续工作

- 首次部署仅可使用 `POST /api/v1/iam/bootstrap/first-super-admin` 创建一次首个超级管理员：配置根目录 `.env` 的 `IAM_BOOTSTRAP_TOKEN`，通过 `X-Bootstrap-Token` 受控调用；成功后清空该配置并重启 API。该接口没有前端页面，不能供普通用户管理操作调用。首个管理员初始化完成后，常规本地账号由 `POST /accounts` 创建，密码初始化和管理员重置分别使用对应的账号密码生命周期接口。
- 管理员重置接口返回的 `temporary_password` 仅在当前成功响应中出现一次。管理员必须立即复制并线下安全交付；前端不得持久化、回显到列表、写入日志或审计。该密码满足强密码规则，重置会撤销有效会话但不会解除已锁定账号。
- `PATCH /accounts/{account_id}` 只允许在 `ACTIVE` 与 `DISABLED` 之间切换，`LOCKED` 由密码登录失败策略维护。
- `Membership` 写入时要求用户、组织和岗位均存在，且岗位属于所选组织；同一用户同一时刻只能拥有一个有效的主任职。
- 已接入路由级权限决策：管理端接口按 OpenAPI 中声明的 `x-permission` 使用统一权限码拦截；未认证返回 `401`，已认证但缺少权限返回 `403`。前端仍不得将按钮可见性视为授权依据。
- 已接入通用审计中间件：用户、账号、组织和任职的写操作以及账号密码生命周期接口会记录操作摘要、身份与请求上下文；密码明文、密码摘要和管理员生成的临时密码不会写入审计事件。
