# 站内信通知开发说明

## 范围

本模块只提供 **站内信** 能力：模板、严格变量渲染、受众解析、消息与收件箱投递、读取状态和失败重试。明确不实现邮件、短信、SMTP、Webhook 或 Redis。

## 已实现模块内能力

- GORM/MySQL 仓储：`notification_template`、`notification_template_version`、`notification_message`、`notification_delivery`。
- 模板创建、版本发布、启停、租户隔离和乐观锁状态更新。
- 变量语法仅允许 `{{identifier}}`；标题和正文均校验声明变量；未知/缺失/超长变量拒绝；值经 HTML 转义后持久化，客户端按纯文本展示。
- `USER`、`ORGANIZATION`、`ROLE` 受众解析仅返回当前租户的启用用户和有效任职。
- 按 `(tenant_id, idempotency_key)` 幂等创建消息；站内信投递只进行数据库状态转换。
- 当前用户收件箱列表、详情、未读计数、单条已读、全部已读。
- 失败投递 `FAILED -> PROCESSING -> DELIVERED/FAILED`、租约锁和指数退避重试。

## 现有迁移核对

`backend/migrations/000022_create_notification_delivery.sql` 已包含本模块所需的四张表、唯一键、收件箱索引和重试索引，**无需新增迁移**。

## 主智能体集成点（不得由本子任务改动共享装配）

1. Bootstrap 使用 `notification/infrastructure.NewRepository`、`NewInboxPolicy`、`NewRecipientResolver`、共享 ULID 生成器和 UTC 时钟创建 `application.NewService`，再创建 `interfaces/http.NewHandler`。
2. 共享 Gin 路由以既有 `adaptHandler` 挂载，并使用现有认证/权限中间件：
   - `GET/POST /notifications/templates`：`platform:notification-template:read/create`
   - `POST /notifications/templates/{template_id}/versions`：`platform:notification-template:update`
   - `PATCH /notifications/templates/{template_id}/status`：`platform:notification-template:update`
   - `POST /notifications/messages`、`GET /notifications/deliveries`、`POST /notifications/deliveries:retry`：运营权限（建议 `platform:notification:operate`）
   - `GET /notifications/inbox`、`GET /notifications/inbox/unread-count`、`GET /notifications/inbox/{delivery_id}`、`POST /notifications/inbox/{delivery_id}:read`、`POST /notifications/inbox:read-all`：仅当前已认证用户。
3. 前端在系统设置/控制台接入 `NotificationCenterModule.vue`；组件只调用当前用户收件箱接口，不传递 tenant_id，也不持久化任何凭据。
4. 共享 OpenAPI 文档需由主智能体按以上路由、状态码及统一响应信封补充。

## 安全边界

- 所有查询和更新同时带 `tenant_id`；收件箱详情/已读同时带 `recipient_user_id`。
- 消息 `target_url` 只允许相对路径，业务页面打开前必须再次做授权判断。
- 模板变量和投递错误不得包含密码、Token、会话、MFA、外部身份或敏感业务正文。
- “投递”不等于推送外部渠道；目前只把已创建的收件箱记录标记为 `DELIVERED`。
