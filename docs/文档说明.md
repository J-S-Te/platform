# 基础能力平台文档说明

本目录是 Basic Platform 项目的**唯一文档根目录**。架构、需求、接口、数据模型、开发说明、专项能力说明、前端说明、OpenAPI 文件和参考原型均统一维护在 `docs/` 中；`backend/`、`frontend/` 等代码目录不保存独立文档副本。

## 目录结构

```text
docs/
├── 项目说明.md                    # 项目介绍、运行方式和常用文档入口
├── 文档说明.md                    # 本文件，定义文档分类与维护规则
├── 01_架构设计/                   # 系统架构、核心模型、平台接入边界
├── 02_需求/                       # 原始需求和领域化拆分需求
├── 03_接口规范/                   # OpenAPI、接口、JWT、数据模型与部署契约
├── 04_后端开发/                   # Gin/GORM、认证、身份、迁移和实施说明
├── 05_能力模块/                   # 审计、通知、可观测性、文件任务等专项说明
├── 06_前端开发/                   # Vue 前端说明、业务模块说明和参考原型
└── 07_项目计划/                   # 开发计划与阶段性实施范围
```

## 权威来源

发生内容冲突时，按以下顺序核对：

1. HTTP 路径、请求响应字段和错误码以[平台接口规范](03_接口规范/平台接口规范.yaml)为机器可读契约，并与实际 Gin 路由和 Handler 交叉验证。
2. 数据库字段、索引和迁移顺序以 `backend/migrations/` 中实际 SQL 为运行依据，[数据模型文档](03_接口规范/数据模型文档.md)负责同步解释。
3. 模块边界、依赖方向和安全原则以[系统架构](01_架构设计/系统架构.md)及[平台接入说明](01_架构设计/平台接入说明.md)为准。
4. 产品范围和验收目标以[原始需求](02_需求/原始需求.md)及[拆分需求](02_需求/拆分需求/说明.md)为准。
5. 已实现能力必须以实际代码调用链、路由注册、GORM Repository 和迁移结果确认，不得只根据函数或模型名称判断。

## 维护规则

1. 新增项目文档必须创建在 `docs/` 的对应分类目录中，不得在项目根目录、`backend/`、`frontend/` 或其他代码目录新增 README 或说明文档。
2. 文档之间使用 `docs/` 内部相对链接；不得引用个人绝对路径，也不得依赖已经移除的 `api/`、`requirements_document/`、`frontend/docs/` 等目录。
3. 文档中的命令统一面向 Linux，并默认使用 Bash 从项目根目录执行；使用 `backend/`、`frontend/` 等项目相对路径，不使用个人主目录绝对路径。
4. 新增或修改接口时，应同步更新 OpenAPI、接口文档、前后端契约、数据模型说明和相关专项开发说明。
5. 数据库结构变更必须新增版本化迁移，并同步更新数据模型文档和数据库迁移说明。
6. 环境变量的可复制模板仍保留在项目根目录 `.env.example`；文档只解释变量用途，不复制真实密钥或密码。
7. 文档文件名使用中文；协议、标准、技术名词和代码标识可保留英文原名。

## Linux 命令规范

1. 项目开发、测试和部署指令以 Linux + Bash 为默认环境，不提供依赖 macOS `brew`、`open`、`pbcopy` 或 Windows PowerShell/CMD 的命令。
2. 首次进入项目时，将下面的占位路径替换为 Linux 主机上的实际仓库路径；后续命令均从项目根目录执行：

   ```bash
   export BASIC_PLATFORM_ROOT="/path/to/Basic-Platform"
   cd "$BASIC_PLATFORM_ROOT"
   ```

3. 开发命令使用项目相对路径；生产示例使用 Linux 标准目录，例如 `/etc/basic-platform`、`/opt/basic-platform`、`/var/lib/basic-platform` 和 `/var/log/basic-platform`。
4. 前端依赖安装优先使用 `npm ci` 和已提交的 `package-lock.json`，不在仓库中保留 `node_modules/`、`dist/`、`.vite/` 等生成目录。
5. Python 辅助命令统一使用 `python3`；Shell 脚本统一使用兼容 Bash 的语法和 `/` 路径分隔符。
6. 需要管理员权限的 Linux 命令必须显式使用 `sudo`，并在执行前确认目标路径、运行用户和文件权限。
7. Linux 的命令名、环境变量名、文件名、目录名、systemd 服务名和 URL 路径都区分大小写。文档中的代码块必须按原样复制执行；例如 `ENV_FILE`、`APP_ENV`、`basic-platform-api.service`、`frontend/nginx/default.conf` 与 `SHA256SUMS` 均不得改变大小写。
8. 文档新增命令时，应优先引用仓库中真实存在的脚本、二进制、配置文件和服务名称；不得把 `Api`、`API`、`Worker`、`worker` 等不同大小写的标识视为可互换名称。
