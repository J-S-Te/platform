# Controlled commercial runtime enrollment

`RuntimeLicenseEnrollmentService` is invoked by the existing authenticated and authorized deployment job, not a browser enrollment endpoint. The composition root supplies an isolated Agent approval source, normal OAuth client manager, and coordination registrar. `ConfigureRuntimeLicenseSettings` supplies the persisted commercial instance/environment and controlled transport paths. Only `ErrRuntimeLicenseNotInitialized` preserves uninitialized legacy deployment compatibility; approval, instance-read, registration and delivery failures close the deployment job explicitly.

The isolated Agent reads `runtime-license-<application>-<OAuth environment>.json` from the fixed deployment directory. Version 1 contains `application`, `environment`, and `components`, each with `service_id`, `protocol: 1`, immutable Docker config `image_digest`, and reviewed entry `coverage_digest`. Both digests use `sha256:<64 lower-case hex>`. The regular non-symlink file may not be group/world writable. Components must match all reviewed profile runtime services, including conditional alternatives. Selection is then restricted to the current actually selected Compose runtime services and rechecked during credential delivery under the deployment lock.

Each component has a separate service OAuth client, single `license.runtime` scope, `client_credentials` grant, and 300-second access token TTL. Its bounded client ID includes a 128-bit hash of application/environment/component, immutable image/coverage, and optional trusted `release_generation`. Same approved release retries preserve identity; changed specs or a new approved generation use fresh clients, so old bearer tokens cannot inherit new confirmation. Returning to an earlier image requires a new approved release generation, not reuse of a retired identity.

Prepare reads the complete current approved set and persisted application revision. First enrollment registers non-legacy members; an existing set changes only via `ReconcileComponents` CAS with a canonical release digest independently re-read by the coordinator's trusted verifier. The fixed Agent release file's optional `retire_service_ids` must explicitly approve removals; members still required by the selected profile cannot be retired. Reconciliation atomically audits old/new specs, retains old-client tombstones, clears prior snapshot/ACK evidence and keeps an activated application restrictive in APPLYING. A retired logical component may return only through an explicitly reviewed release with a fresh client and fresh readiness/ACK. Existing secrets rotate only after registration/reconciliation succeeds. A partial cross-service failure is retriable and is never presented as a whole control-plane/Agent transaction success.

Delivery creates `runtime/license-<service_id>.env` atomically with mode 0600 and rejects runtime/file symlinks. API and Worker secrets are never copied into a shared business environment file and are included in deployment log redaction. Reviewed Compose services must consume their own environment file and mount the trusted public key and independent persistent state path. Unapproved conditional removals fail rather than silently dropping an activation ACK requirement.

Local mutable Docker deployments currently have no approved immutable release source and return an explicit approval-unavailable error after commercial instance initialization. This is not permission bypass or automatic enforcement of uninitialized legacy installs.
