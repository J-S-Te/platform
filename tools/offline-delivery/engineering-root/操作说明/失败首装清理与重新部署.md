# 失败首装清理与重新部署

适用：全新服务器首装失败，确认尚无需要保留的真实业务数据，准备丢弃本次安装重新开始。

脚本位于工作区根目录 `清理首次部署产物.sh`。从 2026-10-23 的打包入口开始，新生成的完整/增量离线包在介质顶层携带该脚本和本说明（包内文件名 `FIRST_INSTALL_RESET.md`），两者均纳入 `SHA256SUMS`；正式签名包还纳入 release manifest 的完整性保护。原有已生成、已签名的历史包不补写。

完成该批介质的原有校验/验签后，可直接在总归档解压目录执行 `sudo bash ./清理首次部署产物.sh --help`，也可单独复制到服务器的 `/root/uip-tools/` 等工具目录。以下命令以单独工具目录为例。依赖 Bash、Python 3 和可访问的本机 Docker daemon，不依赖源码树或部署目录里的脚本。**工具必须位于待删除安装目录之外。**

已有数据的环境应使用现有备份、恢复、`--status` 和 `--resume` 流程；本脚本不能替代生产卸载或灾难恢复。脚本会拒绝升级/增装会话、完成的安装会话、非空安装历史，以及有系统备份但没有可验证未完成首装会话的环境。对于没有新式会话的旧部署，只能依据部署标识和操作者对“可丢弃失败首装”的明确确认，不能自动证明数据库从未被用户使用。

## 1. 先盘点，知道删什么、在哪里

以下命令均在**待重装服务器**执行。工具目录和交付介质目录分开保存；不要向已有签名交付目录添加文件或修改校验清单。

```bash
sudo bash /root/uip-tools/清理首次部署产物.sh \
  --target /opt/unified-identity-platform \
  --plan-file /root/uip-reset-01.json
```

此时不会停止/删除容器，不删除数据卷或安装文件，只新建指定的 0600 计划文件。省略 `--plan-file` 则只显示盘点；`--format json` 可将盘点输出为 JSON。计划路径必须是安装目录之外的绝对路径，已有同名文件不会被覆盖。

2026-10-28 加固版使用 **v2 计划与执行记录**。旧计划不能直接执行，须用新版重新盘点。退出码 `0` 表示本轮操作通过，盘点存在阻塞返回 `2`，校验或执行错误返回 `1`，人工中断返回 `130`。盘点通过只代表允许继续审核，不证明数据库没有真实业务数据。

盘点包括以下实际位置：

| 产物 | 常见位置或定位依据 | 执行清理时如何处理 |
| --- | --- | --- |
| 部署资产、脚本、镜像包副本 | `<target>/bin/`、`packages/`、`subsystems.d/`、`subsystem-templates/`、`mysql-init/`、`nginx/`、`monitoring/` 等；报告逐项列出实际根目录条目 | 随整个安装目录删除 |
| 生成配置、运行批准、授权材料副本、导入记录 | `<target>/.env`、`.release.env`、`runtime/`、`runtime-approvals/`、`license/`、`manifests/` 等 | 随整个安装目录删除；报告不输出配置内容、密码或私钥 |
| 密钥、日志、文件网关对象及上传文件 | 常见为 `<target>/data/platform/`、`<target>/data/file-gateway/`；同时核对实际配置和容器 bind mount | 安装目录内删除；配置指向外部数据目录则阻止执行，不猜测外部目录归属 |
| 安装目录内的备份和暂存事务 | `<target>/backups/`、`.assets-install.*`、`runtime/.assets-install-transaction/` 等 | 有可验证未完成首装会话时随目录删除，包括首装过程自动生成的备份；无该会话却存在系统备份批次时拒绝执行 |
| 安装进度 | `<target>.installation-state/`，包含 `session.json` 和短锁 | 验证首装目标、模式及摘要后删除 |
| 安装历史 | `<target>.installation-history/` | 空目录可删除；非空视为已有安装历史，拒绝执行 |
| 安装执行互斥锁 | `<target>.installation-run.lock` | 保留该 0600 空锁文件；清理时持有同一个锁，避免新安装与清理错用不同 inode；它不保存安装进度，不妨碍重新首装 |
| 平台/业务/基础设施/迁移容器 | Docker 元数据中的 Compose 项目标签、工作目录及编排文件路径 | 停止并删除计划中固定 ID 的容器；先停 provisioner，业务/Worker 随后，MySQL 最后 |
| 数据库、附件、门户报告及许可状态等持久卷 | Docker `volume inspect` 返回的真实 `Mountpoint`；不是硬编码 `/var/lib/docker` | 同项目及卷标签均匹配、被本安装容器引用的普通本机卷可纳入。孤立卷不能仅凭项目名删除，须有原 v2 失败清理记录证明身份。共享、插件或外部挂载选项仍阻断 |
| 项目专用网络 | Docker 网络 ID、项目标签及容器引用，例如 `<project>_docker-control` | 当前仅由本安装容器连接时可纳入；孤立网络须有原 v2 执行记录。无标签网络需显式审核；其他归属/自定义标签不能用放宽选项绕过 |
| 子系统候选容器 | `uip-<子系统>-candidate` 或生产发现标签 | 没有可信安装路径证据，列入阻塞，不按名称批量删除。须单独核对、按受控接入流程处理后重新盘点；其他安装的候选也可能触发保守阻断 |

默认安装目录为 `/opt/unified-identity-platform`，当前新式首装通常写入 `COMPOSE_PROJECT_NAME=uip`。脚本以实际配置和 Docker 元数据为准，不通过容器名 `uip-*` 前缀批量删除。

`.env` 尚未生成或已丢失时，会尝试从**工作目录确实等于该安装路径**的容器推导项目。已知原项目名时可显式指定，例如：

```bash
sudo bash /root/uip-tools/清理首次部署产物.sh \
  --target /opt/unified-identity-platform \
  --project uip \
  --plan-file /root/uip-reset-02.json
```

不要直接照抄 `uip` 来处理其他安装。项目名与 `.env` 冲突、同项目存在其他工作目录的容器，或同一目录绑定多个项目，均会阻止清理。

`--project` 只提供项目名，不证明孤立资源属于本安装。没有旧 v2 执行记录的历史孤立卷/网络需要单独核对，不通过本工具直接删除。

### 1.1 旧版/手工 Compose 遗留的未登记归属资源（2026-10-27 增强）

旧版 Compose、手工 `docker compose` 或历史失败尝试可能创建**缺少 Compose 卷/网络归属标签**的数据卷或网络。当前安装的容器仍在引用它们时，默认盘点会阻断，以免误删其他项目的资源。

确认这些资源确实由本次失败首装产生、且没有真实业务数据后，可显式要求把它们纳入待审核计划：

```bash
sudo bash /root/uip-tools/清理首次部署产物.sh \
  --target /opt/unified-identity-platform \
  --allow-unlabeled-resources \
  --plan-file /root/uip-reset-03.json
```

该选项只允许在生成计划时使用，`--apply` 不接受它。计划会单独列出`拟删除的未登记归属数据卷/网络`及原因；只有**实际标签为空、被本安装容器引用、且没有其他容器共享**的普通本机卷/网络才会进入清单。带其他项目或自定义标签的资源直接阻断，不在删除容器后才拒绝。插件/外部挂载选项或身份变化仍阻断。逐项核对后再审核执行。

## 2. 审核后明确执行

确认盘点报告没有阻塞，且所有需要保留的日志、诊断材料、文件或备份已经复制到安装目录之外。安装目录内的备份也属于删除范围。

```bash
sudo bash /root/uip-tools/清理首次部署产物.sh \
  --apply /root/uip-reset-01.json \
  --confirm-target /opt/unified-identity-platform \
  --discard-fresh-data
```

**此命令永久删除计划中的数据库、业务文件、私钥、运行配置、授权状态和安装记录。** 两个确认参数缺一不可；本脚本没有通用 `--yes`、强制绕过归属或删除保护的选项。

执行前会重新盘点并取得安装长锁、会话锁、发布锁和授权锁。配置、根目录 inode、Docker daemon、容器、卷或网络身份变化时要求重新生成计划。数据文件和日志可继续增长，不靠数据库内容或完整数据文件摘要判断是否为同一清理范围。执行中不要并发运行安装、运维、手工 Docker 管理或修改目标路径。

删除能力和目录权限在停止容器前检查，包括 Python 防符号链接删除能力、删除根的当前用户所有权、目录遍历/写入及父路径权限。通常应使用部署时的 root 用户；工具不因拥有 Docker 权限就假定拥有文件删除权限。普通本机卷还必须能读取真实 `Mountpoint` 的目录 inode，且具有创建时间；缺少这些证据则阻断，不读取卷内业务文件。计划及恢复记录必须属于当前执行用户、权限为 `0600`、为非符号链接的单链接普通文件。预检不能消除后续磁盘、ACL、不可变属性或并发变化造成的所有故障。

逐步记录保存为计划旁的新文件，例如：

```text
/root/uip-reset-01.json.result-20261022T100000.000000Z.json
```

记录区分 `STARTED`、`DONE`、`FAILED` 和 `COMPLETED`，包含脱敏的完整审核范围 `scope` 及摘要；更新采用同目录临时文件加原子替换，写入失败保留上一份完整记录。记录文件是清理后的证据，应保留在安装目录之外。摘要用于一致性检测，不是签名或对恶意管理员的信任证明。

中途失败会停止后续步骤，已成功停止或删除的资源不会自动恢复。容器停止/删除、卷删除或网络删除失败时，安装文件尚未删除；文件删除本身失败则可能留下部分目录。工具会在资源删除前写入 `<target>/.first-install-reset.json`，阻止丢失容器引用后直接普通盘点而漏掉孤立卷。不要删除该标记来绕过恢复门禁。

处理权限/占用原因后，使用**最新的未完成 v2 执行记录**重新生成独立计划（下列时间戳须替换为实际记录）：

```bash
sudo bash /root/uip-tools/清理首次部署产物.sh \
  --target /opt/unified-identity-platform \
  --resume-from /root/uip-reset-01.json.result-20261028T100000.000000Z.json \
  --plan-file /root/uip-reset-recovery-01.json
```

审核新计划后，再以新计划路径执行本节的 `--apply` 和两个确认参数。`--resume-from` 只用于生成计划，不直接删除，也不自动执行旧记录。恢复会继承原项目及无标签资源选项；不能借恢复扩大选项。原资源已删除可略过；卷创建信息或目录 inode 变化、网络 ID 变化、标签变化、共享引用增加、daemon/现存根目录/现存控制文件变化均阻断。文件删除阶段已经移除的标识不要求重新创建，合法原范围和相同根身份用于确认剩余目录归属。资源身份依赖可观察元数据，不能对抗所有元数据及 inode 都被复用或恶意篡改的情况。

恢复记录需保留原路径和权限；安装目录已缺失却仍需删除 Docker 资源时也会拒绝，须单独核对。损坏或缺少原范围的旧版记录不能自动升级为删除授权。锁只协调遵守同一协议的任务；不得并发运维。原子记录保护普通写入失败，不承诺掉电后的完整持久恢复。

清理成功后脚本会核对安装目录、会话/历史、项目容器、候选容器、项目数据卷/网络（含经审核纳入的未登记资源）及安装长锁，打印`重新首装前置检查：通过`，并写入 `"reinstall_ready": true`。该状态只针对本次审核范围，不能证明全宿主机没有其他无标签孤立资源，更不表示完成生产卸载。若该项不是 true，不要直接重新首装。

## 3. 明确保留哪些东西

以下资源没有本次部署前的创建基线，可能早已存在或被共享，因此列出但不自动删除：

- 原始交付目录、总归档、SHA256/签名材料、外部输入许可证；安装会话存在时报告其实际路径。
- Docker 镜像缓存和全部标签。容器的镜像 ID 及 `manifests/*.imported` 中的来源 ID/镜像引用可在盘点中核对；镜像导入前即失败且未形成记录时，不能反推出完整导入范围。重新部署可复用缓存，不执行镜像或全局 `prune`。
- 共享容器 `uip-offline-registry`、卷 `uip-offline-registry-data`；卷的实际存储路径会显示。
- 编排明确声明 `external: true` 的共享网络 `basic-platform-production`。
- Docker 本身、宿主依赖、APT/DPKG 状态、Docker 配置、防火墙规则、独立信任材料和 release-verifier。不会自动卸载或恢复宿主系统配置。
- 其他安装/项目的容器、卷、网络以及临时路径模式 `/tmp/uip-*`、`/var/tmp/uip-host-dependencies.*`、交付目录旁 `.uip-delivery-extract.*`。这些模式不能证明具体目录属于本次安装，脚本不会用通配符删除。

如果问题就在共享 Registry、共享网络、宿主 Docker 或防火墙，本脚本的业务安装重置不会修复这些公共设施；报告中的保留清单用于进一步定位，不宣称机器恢复为安装 Docker 前的状态。

## 4. 重新首装

确认执行记录为 `COMPLETED` 后，从原交付工具位置重新执行原来的安装命令，明确首装和目标路径，例如：

```bash
sudo bash /root/uip-tools/服务器一键离线部署.sh \
  --media /root/uip-delivery \
  --target /opt/unified-identity-platform \
  --install
```

这里的工具和介质位置仅为示例；应换成服务器实际路径，并保留原部署所需的发布验签及其他选项，不能为了重装关闭原有校验。

重置后重新生成密钥、管理员配置及授权实例身份；原有已签发商业许可证可能需要重新申请。需要保留原实例身份时应选择恢复/续跑，而不是清空重装。历史包缺少清理工具时，应使用另外核对过来源的独立工具，或重新制作完整的新发行；不要修改旧包、签名或校验清单。

## 5. v1 清理记录与 v2 脚本

如果恢复记录没有 v2 的 `scope.version`、资源指纹或 checksum，v2 清理脚本会拒绝把它当作自动清理授权。旧版 v1 记录不能直接证明孤立卷/容器的归属；不要手工修改记录冒充 v2。

此时先保留原记录和 Docker 元数据，执行只读盘点，逐项核对卷的 Compose 项目/卷标签、CreatedAt、Driver 和空目录证据。确认是本次失败首装产生、且数据可丢弃后，再按 v2 计划重新盘点并审核；无法确认归属的资源不要删除。需要保留实例身份时使用恢复/续跑，不要清理重装。

对于项目标签正确、但当前容器已不再引用的 v1 孤立卷，可在人工核对后使用：

```bash
sudo bash ./清理首次部署产物.sh \
  --target /opt/unified-identity-platform \
  --confirm-orphan-volumes \
  --orphan-volume-since 2026-10-28T00:00:00Z \
  --plan-file /root/uip-reset-orphan.json
```

该选项只把 **项目标签匹配、当前没有容器引用、CreatedAt 不早于时间窗、Driver=local 且目录为空** 的卷纳入计划；非空卷、外部/插件卷、共享卷仍会阻断。生成计划后必须逐项审阅，再用原有 `--apply ... --confirm-target ... --discard-fresh-data` 执行。缺少 v2 记录时不要自动删除容器、网络或非空卷。
